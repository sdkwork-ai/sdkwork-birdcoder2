# @deepseek-ai/dsh-client-ui-sdkwork-workspace-row-menus

[English](README.md) | 中文

## 概述


SDKWork fork 插件：侧边栏工作区浏览区的行操作菜单——工作区（项目）`⋯` 菜单、会话 `⋯` 菜单、项目行右键菜单——从 `ui-workspace` 抽离为 fork 自有包，保证 fork 侧菜单扩展高内聚、merge 稳定。

同一个包还拥有工作区的**应用构建动作**：工作区菜单通过 `sdkworkAppBuild` Host Remote 探测该项目，给出「编译」与「打包」两个子菜单——列出该项目各应用根**真实声明**的命令——并把每次运行流式送进一个浮动构建输出面板，任何进行中的任务还可以折叠进对话标题栏的构建指示器。

<a id="what-it-owns"></a>
## 拥有的菜单

- **工作区菜单**（项目行 `⋯`）：打开文件夹、复制路径、在终端打开（路径动作行，仅在有工作目录时可用）、编译、打包、发布项目、重命名、删除工作区（danger）。
- **会话菜单**（会话行 `⋯`）：相同的路径动作行，外加复制会话ID、导出会话日志、发布项目、重命名、分叉会话、归档会话。
- **项目右键菜单**（项目行右键）：与工作区菜单相同的条目，走同一组回调。
- **构建动作行**（工作区菜单）：由对该项目 `apps/` 树的一次探测派生出「编译」「打包」两个子菜单。每一行背后都是该应用根**真实声明**的脚本，因此不会出现点了没反应的行。规范点名但本项目无法构建的族，以禁用备注行呈现并带上原因。宿主判定为不可运行的行同样禁用，且带的是**宿主给出的**原因——跨平台目标（非 Windows 上打 `package:win:x64`、非 Apple Silicon 上打 `mac-arm64`）、工具链未安装（没有 Xcode 却打 `flutter build ipa`、Android 通道没有 SDK）、或脚本点名但树里没有的入口文件（`scripts/build-mini-program.mjs`）。渲染侧只负责把该判定写成文案，绝不自行重推：浏览器或远端组合根本不是构建主机。
- **构建输出面板**：每个已启动的编译/打包任务一张卡片——解析后的命令、工作目录、流式 stdout/stderr、工具自己打印时的实时完成度、取消、最小化与关闭——挂载在 `document.body` 上，因此菜单关闭后仍在，继续展示尚未结束的构建。
- **对话标题栏构建指示器**：进行中的构建折叠进去的位置。每个被跟踪的任务都会在对话标题栏右侧功能区出现一个控件；只要有构建在跑，它就旋转并脉冲呼吸，并带上进行中的数量，点击后列出全部被跟踪的构建——标签、状态、实时耗时、进度条。点击某一行即恢复该任务的卡片（打开详情）。最小化是**按任务**的：可以把一个长打包任务停进标题栏，同时让另一个构建留在面板里。
- 独立 locale 命名空间 `sdkwork-workspace-row-menus`（zh/en）。

菜单壳使用共享的 `ui-primitives` `Menu` 原语（portal、指针离开宽限、danger 样式、子菜单）；本插件只拥有业务菜单项与其派发逻辑。两个 Host RPC（打开文件夹、在终端打开）通过 `Toast` 结果横幅回报结局：成功显示已请求文案，失败显示可重试文案——被拒绝的 `host.openPath` 不会表现为"点了没反应"。

<a id="how-it-integrates"></a>
## 集成方式

`ui-workspace` 仍是表面所有者（行、悬停卡、拖拽、对话框）。其浏览器端注册声明子槽 `sidebar.workspaces.rowMenus` 并通过 `renderSlot` 渲染；本插件将菜单渲染器注册进该槽。槽位空缺时浏览器回退到内置的上游菜单实现，因此不带本插件的组装保持原版行为。

动作（重命名/分叉/归档/删除）仍由浏览器持有：菜单组件接收行数据与内置菜单相同的动作回调，派发逻辑保持不变。

构建动作这一半**跨包只走注入的 Cordis 服务，不走 import**：本插件提供 `appBuild`（探测 + 运行），行菜单从自己的 inject 面消费它。其背后的宿主能力是可选的——没有 `sdkworkAppBuild` Remote 的组装照常加载本套菜单，只是不显示构建行。

构建指示器通过 `slots.inject` 注册进 `conversation.session.header.utilities`——它是**订阅**该槽位声明而不是**要求**它：不带 `ui-conversation` 的组装会让该条目处于休眠态，而不是让本插件加载失败，正如构建行在没有 Remote 时优雅降级。该条目对槽位归属包只做 type-only 引入（让槽位键进入程序），不产生任何运行期依赖边。

<a id="dev-note"></a>
## 开发备注

`sidebar.workspaces.rowMenus` 槽位与内置回退位于 `ui-workspace`（上游持有的表面、fork 适配的注册），因此上游合并不会与本包冲突：只有本包的渲染器注册与 locale 命名空间是 fork 自有面。

`src/client/appBuild/` 这一域自成一体：`contract.ts`（结构化传输与服务类型）、`catalogCache.ts`（TTL + 并发合并）、`menuRows.tsx`（catalog → 菜单行）、`progress.ts`（从工具自身输出读完成度）、`BuildPanel.tsx`（纯面板组件）、`panelHost.ts`（任务状态、Remote 驱动、React root、标题栏快照）、`BuildIndicator.tsx`（标题栏控件与其列表）。目录类型按结构声明，而非从生成的传输包 import，因此本插件对它没有编译期依赖边。

标题栏表面读取的是**与面板分离的**快照：`AppBuildTrack` 只带标签、状态、完成度与计时，**刻意不带输出行**。标题栏会在每批输出到达时、以及耗时时钟每次跳动时重渲染，把 5000 行日志在单次构建里穿过它拷贝上千次，就是"指示器"和"卡顿"的区别。宿主只在标题栏真正展示的字段发生变化时才发布，因此不带完成度数字的输出批次不产生任何代价。

<a id="model-experience"></a>
## 模型体验

无，因为本包只是人类使用的表面 chrome。行菜单渲染侧边栏条目并派发浏览器持有的动作；它们发出的 Host RPC（`host.openPath`、`host.openTerminal`）只携带一个文件系统路径，自身不注册任何提示词、schema 或结果文本。构建行在宿主上启动包管理器脚本并把输出流式取回——不涉及 provider 请求，也不涉及会话状态。

#### KV Cache effect

无；本包既不组装也不发送 provider 请求。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与暂缓事项

- **行范围** —— 菜单只服务于侧边栏浏览器的工作区与会话行；其余表面仍渲染 ui-workspace 内置的上游菜单。构建行只挂在工作区范围，因为编译与打包作用于项目而非会话。
- **点击前不做桌面门控** —— 派发前不检查没有桌面打开器的 Host（`host.describe.canOpenPath: false`）；被拒绝的 RPC 经结果横幅回报，而不是预先禁用菜单行。
- **只列工作区真实声明的东西** —— 子菜单列出的是 `apps/*/package.json` 里当下存在的脚本。构建命令在整个工具链里都没接线的族（鸿蒙）以禁用备注行呈现而非提供入口；没有 `package:*` 脚本的族会明说，而不是给出空子菜单。
- **构建是宿主进程** —— 已启动的构建跑在宿主上。关闭它的卡片只停止输出流，不停止进程（取消是单独的显式动作）；宿主对并发构建数的上限是 3。
- **完成度是尽力而为的** —— 帧协议本身没有进度通道，完成度只能从工具自身的输出里读：行尾的 `45%`，或 `[3/10]` 步骤标记。两者都不打印的工具得到的是不确定态扫动条，而不是编造的数字；若工具打印的数字表示的不是自身完成度，进度条就可能走错。进程一旦不再运行，条子也不再动——终态行还在扫动会被读成挂死：成功一律填满（无论最后一次打印的数字是多少，因为打包器往往是先停止上报、后停止运行），中途停止的运行保留已经走到的那一段，而完全未知的进度读作空轨道而不是满轨道。耗时与状态文案始终精确。
- **指示器是宿主全局的，不是会话级的** —— 标题栏座位是会话级的，但它背后的构建是从侧边栏启动的宿主进程。每个打开的会话看到的是同一份列表，因此从某个工作区启动的构建，在操作者当前看的任意会话里都能找到。
