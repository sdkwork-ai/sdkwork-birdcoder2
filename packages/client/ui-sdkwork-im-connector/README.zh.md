# @deepseek-ai/dsh-client-ui-sdkwork-im-connector

[English](README.md) | 中文

## 摘要

IM 链接器的产品表面：模式栏 `mode.rail.panel` 座位中的一个快捷图标，紧挨在设置图标上方，以及它打开的 keyed `mode.page`。点击快捷图标会把框架切到链接器自己的 `im` 模式页，由该页渲染内嵌 `@xmanrui/dsh-im` 插件通过 `dshImClient` v1 发布的 IM 管理面板。这个表面与应用商店等模式页一致：左侧只有图标栏，右侧是页面内容，不显示工作区/会话侧栏。它使用产品名称「IM链接器」（英文 "IM connector"）——这是链接器的角色，而不是插件内部「IM机器人」的面板文案——图标为[双对话气泡连线造型](src/client/ImConnectorIcon.tsx)，采用模式栏的细线权重。

页面始终渲染完整的管理界面。渲染只依赖插件的面板服务，不依赖任何渠道是否已连接或已绑定：账号未链接、机器人已停止或网关不可达时，渠道卡片、扫码流程和设置仍然完整显示，并由面板自己的状态说明描述失败原因。快捷入口与页面只在服务存在期间出现，因此没有组合 IM 插件的部署不会出现死图标，插件卸载后两处注册也会一起移除。

左侧栏快捷入口就是该面板唯一的导航入口：`ui-sidebar` 会把已在 `mode.rail.panel` 中暴露的面板从其 `sidebar.panellist` 行列表中过滤掉。快捷入口使用插件公开的面板 id（也是它自己那一行使用的 id）注册，因此 IM 面板不会在侧栏中重复出现。

## Model Experience

无。本包只承载面向人的界面入口；打开 IM 面板只改变浏览器中的查看状态，不会进入模型请求。

#### KV Cache effect

无；本包既不组装也不发送模型请求。

## 已知限制与后续工作

- **面板身份是公开字符串** —— 快捷入口以 `xmanrui-dsh-im`（IM 插件自己的主面板键）注册，以便 `ui-sidebar` 去掉插件重复的侧栏行。上游若重命名，需要更新本包中的常量；插件没有为宿主导出可导入的 id。
- **模式 id 是宿主词汇** —— `im` 由本接入加入 `AppModeId` 与窗口标题字典。若出现第二个 IM 表面，它们会共用这一个模式页。
- **插件自己的文案保持不变** —— dsh-im 在其设置分区和插件详情操作中仍使用「IM机器人」/「IM bots」。只有模式栏入口和模式页标题使用链接器名称，因为宿主不编辑插件的构建产物。
- **插件详情页保留自己的打开操作** —— dsh-im 插件详情里的按钮仍在代码表面选中它的 `main` 面板（显示侧栏），这是与本快捷入口不同的一条导航路径。
- **只跟随编译进来的服务** —— dsh-im 的可选桌面接入还会在本次组合之外注册第二个面板 id（`dsh-im`）；本快捷入口只跟随 `xmanrui-dsh-im`。

### 开发者说明

<details>
<summary>维护者工作背景 —— 点击展开</summary>

模式页与模式栏快捷入口都只是同一个框架事实的投影：内嵌插件发布的 `dshImClient` v1 服务。子级注入持有两处注册，因此服务的生命周期就是导航的生命周期，本包不保存任何状态。模式栏的 `mode.rail.panel` 座位把框架的 `activeMode` 交给入口；页面把 `dshImClient.render()` 包进插件页原本的表面几何中。面板 id 必须保持为插件公开的导航键；不要深入插件的组件树，也不要复制它的面板。

</details>

## Runtime invariants

本包不发布运行时不变式配套模块；两处注册都是对 `dshImClient` 服务的直接投影，注册生命周期、模式切换与选中态样式均由本包的客户端行为规格直接覆盖。
