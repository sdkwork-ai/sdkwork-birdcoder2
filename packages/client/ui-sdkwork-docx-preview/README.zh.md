# @deepseek-ai/dsh-client-ui-sdkwork-docx-preview

[English](README.md) | 中文

## 概述

在右侧边栏的文档标签页中绘制 `.docx` 文档。本包在文档注册表中认领文字处理后缀，然后贡献键控主体：页面流式排布在带编号的缩略图栏旁，提供缩放、翻页，以及节自己的页眉和页脚。解析在浏览器内完成，输入是文档属主已经读取的包字节，解析过程还原样式级联、编号计数器和节几何，因此页面的排版与 Word 一致，无需服务器、转换器或网络往返。

<a id="注册内容"></a>
## 注册内容

- **渲染器元数据** —— `ctx.documentPreviews.register(...)`，id 为 `@deepseek-ai/dsh-client-ui-sdkwork-docx-preview/docx`，后缀 `docx`、`docm`、`dotx`、`dotm`、`doc`，`loading: 'bytes-complete'`。不设置 `priority` 时注册落入 `extension` 档，高于 builtin 档，因此文档永远不会退回纯文本阅读器。`bytes-complete` 让文档属主走它现有的 `readAll` 路径，本包自身不做任何文件读取。
- **主体** —— 同一 id 下的键控 `sidebar.right.tab.document` 席位，位于注册声明的 Session 作用域 store 中。主体接收 `resourceAddress`、`content`、`wrap`、`scrollportRef` 和 `useTabInfo`；文档工具栏之下的全部内容归它所有。舞台元素就是渲染器的滚动端口，属主借此在重挂载之间恢复上次的滚动偏移。
- **共享查看状态**，按标签页 id 分桶：选中页与缩放（`'fit'` 或固定倍数）。store 比主体卸载活得更久，因此切换标签页再回来仍停留在原来的页面。

`doc` 是有意认领的，尽管渲染器无法绘制这种旧版二进制格式。若不认领，文件会落到纯文本阅读器并报告"可展示的文件不是文本"；认领它让主体说明真实原因并给出修复办法。

<a id="渲染方式"></a>
## 渲染方式

- **容器与部件** —— 共享 OOXML 库从中央目录读取 OPC 包；`document.ts` 走包根 → 主文档 → 样式、编号、设置、主题、媒体，以及各节的页眉页脚。没有页眉或页脚部件的节继承上一节的；连续分节符并入共享页面而不新开一页，除非该分节符自带页眉页脚。
- **样式** —— `format.ts` 把一个属性元素读成部分格式，`styles.ts` 将 `w:docDefaults` 与 `w:basedOn` 链合并，`content.ts` 再叠加段落标记、`w:rStyle` 命名的字符样式和运行自身属性。表格样式的 `w:tblStylePr` 条件带（首行、隔行、隔列、末行）随表格的 `w:tblLook` 一起解析：它们的底纹与边框装饰覆盖到的单元格，其运行属性按级联落在这些单元格所含块之下。
- **行布局** —— 倍数形式的 `w:spacing/@line` 以字体的自然行为单位计数（与 Word 相同），因此主体对每个字体探测一次自然行高，把倍数换算为绝对行高；exact 与 atLeast 规则本身就是像素。Word 把上一段的段后距加到下一段的段前距上，所以流式外边距按块列表预计算，页首块丢弃段前距，空段落的高度恰好是段落标记一行的高度。
- **编号** —— `numbering.ts` 为每个编号实例维护一组计数器并渲染各级 `lvlText`，于是 `%1.` 成为递增序数，`%2)` 成为字母，项目符号保持符号。
- **内容** —— 段落、超链接、修订插入、简单与复杂域、制表符、符号、换行与分页、图片。`w:sdt` 内容控件是透明的：其中包裹的段落、表格与运行照常读取；`w:del` 被跳过，`w:vanish` 的运行不绘制。外部超链接只接受 `http`、`https` 和 `mailto`；文档内链接把舞台滚动到持有对应 `w:bookmarkStart` 的段落。
- **分页** —— `paginate.ts` 依据测量高度把节的块分到各页，遵守显式分页、`w:keepNext` 链和 `w:keepLines`。跨越页边界的段落在行边缘拆分——两侧各保留至少两行，即 Word 默认的孤行寡行规则——表格在行间拆分，并在续页重复 `w:tblHeader` 行；被纵向合并跨越的切点会让整张表移动。主体在内容宽度的隐藏容器里完成测量。
- **表格** —— `table.ts` 解析网格、合并跨度和嵌套表格，`render/` 绘制真正的 HTML 表格，单元格摆放交给浏览器。纵向合并的续格按网格列匹配；上方没有 restart 的续格绘制为空；单元格自身的边距和 exact 行高（裁剪）覆盖表格默认值。

媒体部件在解析文档时创建 Blob URL，并在创建它们的效果中撤销，因此切换文件或关闭标签页不会泄漏。

<a id="交互"></a>
## 交互

缩略图栏按文档顺序列出每一页的实时缩略图；选中页带 `aria-selected` 与品牌色边框。页面只在缩略图栏视口附近绘制，长文档只保留几十个活跃画布而非数百个，且缩略图栏会滚动到选中页。标签页宽度低于 520 px 时缩略图栏折叠，舞台占满宽度。

工具栏支持上一页/下一页、按步进缩放、回到 `1:1`、切换适应窗口；适应按钮兼作缩放读数，`Ctrl` + 滚轮也可缩放。`PageUp`/`PageDown` 翻页；方向键先滚动页面、到达边缘才翻页，与 PDF 阅读器一致；`Home`/`End` 跳到首页与末页。对辅助技术而言每一页是一张图片，并由它自己报出页码。

## 已知限制与暂缓工作

<a id="known-limitations-and-deferred-work"></a>
- **旧版 `.doc` 只说明、不绘制。** Word 97–2003 二进制格式是完全不同的容器；主体会报告原因并给出修复办法，而不是显示空页。
- **分页是估算而非重排。** 一页装不下的表格行整体移动而非按行拆分，因此高于一页的行会被裁剪；被纵向合并跨越的切点让整张表移动而不是续接单元格。
- **锚定图片按文本流摆放。** 会读取 `wp:anchor` 的尺寸，但浮动图片或形状画在其锚点所在位置而非绝对偏移，文字也不会绕排。
- **`PAGE` 与 `NUMPAGES` 之外的域显示缓存结果。** Word 把上次计算的文字存在文件里，其他域绘制的正是它；刷新域或计算公式需要排版引擎，不是阅读器。
- **公式、嵌入对象与文本框不绘制。** Office Math 渲染其回退文本，OLE 对象或图表渲染为占位说明，`w:txbxContent` 文本框不绘制。
- **脚注和尾注不读取。** 脚注部件及其引用不绘制任何内容。
- **制表位不绘制前导符。** 自定义停止位会让后续文字按左、居中、右的方式排布，但 Word 沿运行绘制的点线或虚线前导符不会绘制，居中停止位在相邻内容之间取平衡而非精确停在声明位置。
- **嵌入字体不解码。** 混淆的 `odttf` 部件回退到查看器字体；依赖嵌入字体的文档按回退字体的度量排版。
- **Word 的文档网格与中日韩行距未应用。** 忽略 `w:docGrid` 与 `w:snapToGrid`，对齐文档网格的文档与 Word 的行密度略有差异。
- **Word 的 autofit 列平衡是近似的。** 未声明 `w:tblLayout w:type="fixed"` 的表格交由浏览器的表格算法按内容平衡声明的列宽；Word 用自己的 autofit 启发式分配剩余空间，因此这类表格的列比例可能与 Word 不同。
- **从右到左的细粒度顺序遵循浏览器规则。** `w:bidi` 设置段落方向、`w:bidiVisual` 反转表格列序，但行内混排文字的细粒度顺序由浏览器自身的 bidi 布局决定，与 Word 的精确算法可能存在差异。

### 开发备注
