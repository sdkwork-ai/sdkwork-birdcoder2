# Web Development

Build or change web features with a working, verifiable result.

## Workflow

1. Identify the page/component surface and the data it needs; sketch the component and state layout before editing.
2. Follow the project's front-end stack and conventions (component structure, styling system, routing, i18n for user-visible copy).
3. Wire data through the project's existing service/query layer; never assemble raw HTTP/auth concerns inside components.
4. Cover states: loading, empty, error, and success. Keyboard behavior and visible focus are part of done.
5. Verify with the project's own checks (typecheck, tests, build) and describe how to see the result in the running app.

## Output

State the routes/components touched, the data flow, and any follow-up (a11y, performance, i18n) the change implies.
