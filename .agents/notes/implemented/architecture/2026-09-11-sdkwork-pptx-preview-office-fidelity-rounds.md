# Agent Note: The PowerPoint preview draws masters, fallbacks, and freeform geometry like Office

Status: implemented

English | [中文](2026-09-11-sdkwork-pptx-preview-office-fidelity-rounds.zh.md)

## Problem

The first renderer ([2026-09-10](2026-09-10-sdkwork-pptx-preview-ooxml-renderer.md)) drew a slide's own shapes over an inherited background fill, which reads correctly only for decks built from the default template. Against real commercial decks two regression passes found twenty-plus gaps: the renderer read only the first slide master, so a deck that switches design per section took wrong colours and fonts from that point on; the logo bars, decorative rules, and footer shapes that live on masters and layouts never drew at all; tables parsed as placeholders because `readTable` looked the graphic up in the PresentationML namespace instead of DrawingML; charts and SmartArt — which Office saves with a cached fallback picture wrapped in `mc:AlternateContent` — fell to a "not supported" label; freeform icon art (`a:custGeom`) fell to a rectangle; exact line spacing (`a:lnSpc/a:spcPts`) rendered as a unitless multiplier tens of times too tall; stretch blip fills cropped like `cover` instead of filling the frame; and a hostile container could drive unbounded allocation because the ZIP reader set no inflation caps. Thumbnails mounted one full element tree per slide, and the read-back offered no wheel zoom, no Home/End, no hidden-slide marking.

## Decision

Two passes, both inside the existing parse → model → CSS projection, with no new dependency:

- **The document graph resolves per master.** Every declared master is read with its own theme, colour map, and text styles; each layout resolves through the master its own relationships declare (lazily, cached by part name, falling back to the first master when the chain is broken). Non-placeholder shapes on the master and layout flatten ahead of the slide's own shapes in Office's paint order, and `showMasterSp="0"` on a slide or layout suppresses the master layer.
- **What Office caches, the preview shows.** `mc:AlternateContent` frames draw their `mc:Fallback` — the cached picture Office rendered for charts, SmartArt, and equations — at the frame's position and size. Freeform geometry projects to a CSS `path()` clip scaled from the path's own coordinate space (arc segments degrade to a line toward their end vertex). Clipped outlines stroke along the geometry as a second colour band under the scaled-in fill, not a box border that clips into fragments; connectors grow the arrowheads their `a:ln` names.
- **Text metrics follow Office.** Percentage line spacing renders as a multiple, exact `spcPts` as a pixel height; `buSzPct` sizes a bullet against its own run rather than a fixed base; a colourless bullet takes its first run's colour; wavy/double/dashed underlines and run shadows map to their CSS forms.
- **Tables get Office's default look.** Where cells state no fill and `tblPr` asks for a header or banding, the parser bakes the theme's first accent into header fills, tinted band rows, and bold white header text at parse time, because the render model holds no theme.
- **The container is bounded.** The shared foundation's ZIP reader caps inflation per entry (256 MB) and per package (512 MB), refusing a lying central directory instead of allocating it.
- **The preview edits.** Text edits apply to the render model immediately (WYSIWYG) and persist by rewriting only the touched slide XML, notes parts, relationships, and content types inside the original container; the notes pane is always editable, creating a minimal notes part for decks that never had one.
- **Internal jumps navigate.** A hyperlink authored as a jump to another slide carries a `#slide/N` marker the body's delegated click handler turns into a page change; the slide part index is resolved ahead of the walk, so forward references work. The open `arc` preset paints as a stroke-width band along the sampled ellipse, and a frame stating `numCol` flows across columns.
- **Tables resolve their real style.** The presentation's `tableStyles.xml` part is parsed per style id, and `readTable` walks role parts (first/last row and column, row and column bands, whole-table) in Office's specificity order, resolving the style's scheme colours against the reading slide. A dark resolved header fill turns its default-coloured runs white and bold; tables without a style part keep the accent heuristic.
- **Links and header/footer fields are live.** A run carrying `a:hlinkClick` keeps its link when the relationship resolves to a web or mail URL — the scheme whitelist keeps `javascript:` and friends as plain text — and an unstyled link paints in the theme's hlink colour, underlined. Footer, date, and slide-number placeholders draw when their `p:hf` flags enable them; the decoration trees fold per slide, so the `slidenum` field carries each slide's real position instead of the producer's cached text, and a layout's own placeholders suppress the master's copies of the same type.

The rail mounts thumbnails through one shared IntersectionObserver, steps zoom with Ctrl+wheel around the viewport centre (a native non-passive listener, because React registers wheel handlers passively), keeps the selected thumbnail in view, and marks hidden slides. `+`/`-` step the zoom and `0` returns to `1:1` at the stage. The parser yields between slides so a large deck cannot hold the main thread, and releases its media Blob URLs on a parse failure as well as on success.

## Alternatives considered

**Resolve `tableStyles.xml` fully.** The style part's fill/effect matrix could colour every built-in style exactly. The flag-driven accent heuristic covers what default-styled tables look like at a fraction of the parser, so the full resolver waits until a deck shows the difference.

**Render live charts and SmartArt.** Drawing the chart model or the diagram layout engine is a standalone fidelity project; the cached picture is what Office itself shows in reduced-fidelity contexts, and decks always ship it.

**Rewrite rendering on canvas or SVG.** A full vector surface would make custGeom and strokes exact, at the cost of the pure model → CSS projection the keyless tests assert against, text that stays selectable and zooms crisply, and the layering the text frame relies on. The band technique and `path()` clips buy the same outline fidelity inside the existing projection.

## Consequences

Commercial decks keep each section's theme, draw their template furniture, show their charts and icons, set text at Office's metrics, and carry working footers, slide numbers, and web links. The known-limitations lists in both READMEs now name what remains: `tableStyles.xml` accents beyond the first, the open `arc` curve and fixed-polygon adjustment values, internal slide-jump links, WordArt effects beyond shadows and underlines, and the text fitter. Shape shadows read their real direction, distance, blur, and colour instead of a fixed approximation, media bytes evict from the package cache once converted to Blob URLs, and numbered bullets render lowercase romans, uppercase alphas, and parenthesised forms exactly. Coverage pins every new behaviour: per-master themes and decoration suppression, fallback unwrap, custGeom projection, the stroke band, arrowheads, exact line height, percent bullets, inflation caps, lazy rail mounting, wheel zoom, Home/End stepping, hyperlink resolution with its scheme whitelist, `p:hf`-gated placeholders with live slide numbers, and the ring and band presets.
