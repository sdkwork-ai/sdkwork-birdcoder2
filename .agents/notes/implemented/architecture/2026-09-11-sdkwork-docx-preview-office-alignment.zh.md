# Agent Note: Word 预览按 Office 方式拆分流式块、解析表格样式并校准行度量

Status: implemented

[English](2026-09-11-sdkwork-docx-preview-office-alignment.md) | 中文

## 问题

第一版渲染器按整块分页：跨越页边界的段落会整体挪到下一页，于是页面在只填到一半高度时就结束，长段落甚至会被直接裁掉。以一组样本对照真实 Word 输出（每个样本由 Microsoft Word 自己转成 PDF）进行回归，两轮共发现二十多个缺口：`w:spacing/@line` 完全无效，因为每个运行都画着写死的 1.25 行高并覆盖了段落的行距；CSS 外边距折叠取相邻段落间距的较大值，而 Word 是相加；空段落只有一个默认行高，而不是段落标记的高度；页首绘制段前距，Word 在页首会抑制它；表格条件格式（`w:tblStylePr`）从未解析，带样式的表格画成裸表；纵向合并的续格按单元格序号匹配，横向跨度一旦移动行就会落错列；没有可绘制图片的 `v:shape` 静默消失；`titlePg` 与奇偶页眉在缺失部件时回退到默认部件，而 Word 本应不画；高于页边距的页眉页脚覆盖正文；`w:pgNumType/@start` 不生效；连续分节符被当成强制分页；没有页眉部件的节完全丢失上一节的页眉页脚；外部超链接接受包括 `javascript:` 在内的任意 scheme；缩略图栏为每一页挂载完整的页面树；方向键直接翻页而不是滚动。

## 决策

两轮改造，都留在既有的解析 → 模型 → CSS 投影之内，不引入新依赖：

- **流式块在真实边缘拆分。** 分页消费测得的内容高度与逐块流式外边距，把拆分委托给以实时 DOM 映射为后端的拆分器：段落在行盒边缘拆分（两侧各保留至少两行，即 Word 默认的孤行寡行规则；`w:keepLines` 整体移动），表格在行间拆分，续页重复 `w:tblHeader` 行，并拒绝被纵向合并跨越的切点。测量容器恰好在每一轮运行期间存在，拆分读取的是真实几何，随后容器卸载。
- **行度量跟随 Word。** 倍数形式的 `w:spacing/@line` 以字体的自然行为单位，因此主体对每个字体探测一次自然行高（按字体族缓存），把倍数换算为绝对高度；exact 与 atLeast 规则保持像素。流式外边距把上一段的段后距并入当前块的顶部，页首块丢弃段前距，段落标记的字体决定空段落的高度。
- **表格解析声明的样式。** `w:tblStylePr` 条件带（首末行、首末列、横向与纵向条带）沿样式的 `basedOn` 链在表格 `w:tblLook` 约束下解析：条带的底纹与边框装饰其覆盖区域的单元格，条带的运行属性按级联落到这些单元格所含块的段落样式之下——单元格的块在网格定位之后读取，下垫层恰好落在条带所在之处。纵向合并的续格按网格列匹配；上方没有 restart 的续格绘制为空，并像 Word 一样丢弃其内容。逐单元格的 `w:tcMar`、`w:tblInd`、exact（裁剪）与 atLeast 行高，以及按比例拉伸的百分比 `w:tblW` 都遵循文件。
- **节的行为与 Word 一致。** 没有页眉页脚部件的节继承上一节的故事；`titlePg` 与奇偶选择在部件缺失时什么也不画而不是回退；高于页边距的故事把正文区域向下推（ResizeObserver 测量，字体落定后重跑）；`w:pgNumType/@start` 播种阅读器在 `PAGE` 域看到的编号，节的延续按此推进；连续分节符共享页面，除非它自带页眉页脚。
- **链接过滤且内部链接可导航。** 外部关系只回答 `http`、`https` 和 `mailto`——其余一律渲染为带样式的文本；`w:anchor` 链接把舞台滚动到持有对应 `w:bookmarkStart` 的段落（用 `data-` 属性，名为 DOM 全局的书签无法污染任何东西）；没有可绘制图片的 `w:pict` 会说明对象而不是消失。
- **缩略图栏可扩展且按键符合预期。** 缩略图通过一个 IntersectionObserver 只在栏视口附近绘制，栏滚动跟随选中页，`PageCanvas` 已 memo 化且 `<img>` 懒加载，栏在 520 px 容器查询以下折叠，舞台获得焦点环，方向键先滚动到页面边缘再翻页（附 `Home`/`End`），Ctrl+滚轮经非被动原生监听缩放，因为 React 注册的 wheel 处理器是被动的。

Word 主体只在值变化时重置查看状态（以新数组身份清空页面列表，会让收到不稳定 tab 属性的重跑陷入循环），且页眉推挤、比率探测与收尾轮会在 `document.fonts.ready` 之后重跑，让迟到的字体在读高度之前完成校准。

**第三轮把回归扩展到纯净样本组覆盖不到的场景。** 针对全新样本（从右向左文字、高于页边距的页眉、纵向/横向/纵向三节、26 页大文档）的又一轮回归修复了剩余的结构性缺口：文档的默认字符样式把文档默认值重新施加到段落级联之上，踩掉了所有段落级取值（Title 渲染成正文大小）；编号计数器改按抽象编号定义共享，共享同一抽象编号的实例像 Word 一样接续计数，而实例自己的 `startOverride` 仍会重启本级；未声明 `w:tblLayout w:type="fixed"` 的表格改用浏览器按内容驱动的布局（内嵌表格会撑宽所在列，auto 宽度的表格紧贴文字）；边框完全一致的相邻段落绘制为一个共享边框盒，而不是每段一条线；分页循环让拆分后的尾部在新页面上继续参与竞争，跨页表格不会再裁掉剩余行；从右向左段落按 Word 的读法交换 `left`/`right` 对齐边。

**第四轮补齐了剩余的内容丢失与导航缺口。** 结构化文档标签（`w:sdt`）在块级与行内级都做透明解包，模板内容控件与其中存放的目录照常读取（正文遍历、单元格读取器与行内读取器都会递归进入 `w:sdtContent`，控件内的分节符依然生效）。自定义制表位（`w:tabs`）将后续文字按声明的左、居中、右停止位以 flex 分段排布——复现左/中/右页脚与目录的右缘页码；前导符仍不绘制。工具栏的页码计数器升级为可编辑的页码框（输入数字回车跳转），并按分页范围钳位。

**第五轮覆盖了引用标记、可访问名称与阅读缩放。** 脚注或尾注引用在正文中渲染其上标序号标记（脚注文字本身仍是已记录的限制）；图片的 `wp:docPr/@descr` 成为其可访问名称；适应切换新增适宽模式以填满面板宽度，让宽表格与横向页在窄栏中保持可读。

**第五轮覆盖了东亚缩进、从右到左表格与翻页体验。** Word 为东亚文档书写字符单位的缩进（`w:ind w:firstLineChars`、`leftChars`、`hangingChars`、`rightChars`）；段落会按段落标记字号换算这些值，并覆盖相应的缇值。`w:bidiVisual` 反转表格列序并镜像水平边框，使阿拉伯语与希伯来语表格自右向左阅读。翻页时舞台滚动回到新页顶部。

## 被否决的替代方案

**真正的排版引擎。** 行级分页而不重排，保住了模型 → CSS 投影和作为断行器的浏览器；完整引擎（或 OnlyOffice 级别的重写）被否决，因为它会放弃无键测试所断言的纯模型。代价已被记录：高于一页的表格行被裁剪而非按行拆分，被纵向合并跨越的切点让整张表移动。

**拆分超高行的单元格。** Word 会把一行文字跨页续排；这需要逐单元格的列测量与重组，所以拆分拒绝该切点并移动整表——损坏比粗糙的断点更糟。

**在 worker 中解析。** worker 里没有 `DOMParser`，解析就得换一套 XML 栈，而收益只限于超大文件；解析逐部件让出主线程，留在主线程上。

## 后果

真实文档像 Word 一样流式排版：段落在行边缘从句中换页且孤行寡行受保护，表格在重复表头下跨页续排，带样式表格呈现条带外观，标题与后继同页，页脚从节自己的起始值计数。行密度跟随实际字体：短样本的断页位置与 Word 完全一致，五页样本在全文长度上漂移一页，因为 Word 的文档网格行距增加了投影未建模的逐行空间。两份 README 的已知限制清单列出了剩余项：表格行内拆分、锚定图形的偏移与文字绕排、`PAGE`/`NUMPAGES` 之外的缓存域结果、公式、OLE 对象、文本框、脚注、自定义制表位、嵌入字体、文档网格与完整 bidi 镜像。覆盖测试钉住每一项新行为：段落与表格拆分的孤行规则和表头重复、按网格列的合并匹配与孤儿续格、`tblLook` 下的条带解析、故事继承与空白首页页眉、连续合并、`pgNumType` 编号、链接 scheme 白名单、含 keepNext 优先级与退化高度情形的拆分钩子分页，以及流式外边距算术。
