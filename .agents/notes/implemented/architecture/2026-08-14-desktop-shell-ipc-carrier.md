# Agent Note: The Electron desktop shell — the IPC fetch carrier and the desktop carrier swap

Status: implemented

English | [中文](2026-08-14-desktop-shell-ipc-carrier.zh.md)

## Problem

The [gui layering and RPC protocol note](../../archived/architecture/2026-07-19-gui-layering-and-rpc-protocol.md) reserved an Electron shell that reuses the web client packages over an IPC fetch carrier: the `AbstractApiClient` subclass table named an "IPC bridge subclass" with no shell behind it, the webserver README stated the server serves browsers only, and the four-quadrant RPC protocol was deliberately channel-independent so a new carrier could swap in without touching the contract. The reservation needed a concrete realization: a desktop application that boots the same harness tree as `dsh web` with zero network ports, serving the built frontend and plugin bundles from the local shell and carrying RPC over IPC.

## Decision

The desktop shell is `apps/desktop` (`@deepseek-ai/dsh-desktop`, Electron): it boots the canonical `web` profile in-process through the same `dsh-app-boot` machinery the CLI uses, then applies the installation-owned `@deepseek-ai/dsh-sdkwork-desktop-app` bundle as a runtime overlay without persisting it in the profile manifest. The Harness home is replaceable for tests, and module fallback healing covers the installation plus profile-local plugins. Three pieces realize the carrier swap:

- **The desktop carrier** (`packages/host/sdkwork-desktop-carrier`, `@deepseek-ai/dsh-sdkwork-desktop-carrier`): a `webServer`-service-shaped route/fallback/index-tap registry driven by `dispatch(request)` instead of node:http. The `sdkwork-desktop-app` bundle patch disables the HTTP `webserver` row and inserts this row, so client-modules (plugin bundle route + boot-manifest index tap), frontend-static (dist fallback), ui-theme (index tap), and web-runtime mount unchanged. The Electron main process registers the `app://` scheme as privileged (standard, secure, fetch-capable, CORS-enabled, streamable) and routes every request for the single `app://dsh` origin through the carrier's dispatch, which runs handlers against a node:http-shaped request/response shim (the handlers read `req.method`/`req.url` and write `res.writeHead`/`res.end`; the shim materializes the collected response).
- **The IPC bridge** (`dsh-client-connection`'s new `/desktop` node half, `src/desktop.ts`): provides the `desktopBridge` host service — the unary/respond fetch handler built from the web node half's `HostConnectionService.createSharedFetchHandler` over the shared `createApiGatewayFetch` (privileged-method pinning included), plus `api.events.mux`/`host` openers. The web `connection` row stays mounted: its `/api` route and WebSocket upgrade registrations land on the desktop carrier and are inert, and the row is what carries the connection browser half into the `__DSH_BOOT__` graph — disabling it would remove the renderer's wire client. The main process wires `ipcMain.handle('dsh:rpc'|'dsh:subscribe')` and `webContents.send('dsh:frame'|'dsh:stream-end')` to the bridge, normalizing every renderer request to the loopback authority (the desktop analogue of the same-origin loopback page the /api fence grants).
- **The renderer client** (`dsh-client-connection`'s browser half): the connection plugin's apply selects the carrier on the preload-exposed `window.desktopBridge` — present → `IpcApiClient` (an `AbstractApiClient` subclass whose `doFetch` rides the bridge's JSON round trips and whose `openMux`/`openHost` ride per-subscription downlink callbacks) plus `createIpcConnectionRpc`; `?fixture` → the fixture; otherwise the WebSocket `WebApiClient`. The selected IPC carrier also makes `ctx.connection.isLoopback` true independently of the `app://dsh` hostname: the preload bridge identifies the local in-process carrier, while `WebApiClient` continues to classify the current page hostname. Client settings scopes and native-action controls therefore expose the same local-only operations as a loopback web page. The sandboxed preload (`apps/desktop/src/preload`) exposes the bridge with `contextBridge` and `ipcRenderer` only.

The shell window uses `contextIsolation: true`, `nodeIntegration: false`, and `sandbox: true`; the preload is a single CJS artifact (sandboxed preloads cannot be ESM). Sessions persist under the standard Harness home (`$DSH_HOME` or `~/.dsh`), sharing data with the CLI and web surfaces. Shutdown disposes the host tree through the same bounded controller pattern as the CLI before exit.

Packaging (electron-builder, `apps/desktop/electron-builder.yml` and the `.github/workflows/desktop-release.yml` release workflow) keeps `asar` OFF: the host heals its per-profile module fallback with junctions/symlinks that must target real directories, and an asar archive is a file, so the packaged layout is `resources/app/` as real files. The app's `dependencies` declare the FULL runtime closure — electron-builder collects only declared dependencies, and the harness's Service Definition packages are peers of their implementations, so every reachable peer must be listed; `apps/desktop/scripts/sync-pack-deps.mjs` computes and synchronizes that list (`check:pack-deps` validates it in CI). The app also assembles its own shipped agent-preset roster (`apps/desktop/config/agent-presets`, packed into the app): the web composition's `agent-presets` row defaults to `standard`, and without a system-trusted root that default resolves nothing, so every `session.create` fails — the desktop host injects the shipped root exactly like the CLI's profile boot does. The release workflow builds on all three platforms, packages Windows NSIS / macOS dmg+zip / Linux AppImage installers, and smoke-tests each packaged boot with `apps/desktop/scripts/packaged-boot-probe.cjs` against a scratch home. The probe fetches every advertised client bundle, creates a session, checks the configuration namespaces, settings clients, and provider directory, writes plugin, model, and credential settings, rejects the credential value in `settings.yaml`, and reads the configuration and value-free credential status after a restart.

## Alternatives considered

| Rejected | One-line reason |
|---|---|
| Loading the dist over `file://` with the manifest injected by the preload | The built index.html uses absolute asset paths, and file pages restrict fetch; the `app://` protocol serves the index through the carrier's existing tap pipeline (boot-manifest injection) and answers every relative asset and bundle URL uniformly |
| A clean-room desktop bridge replacing the web node half | Reusing `HostConnectionService` + `createApiGatewayFetch` keeps generic RPC channels, interceptors, and privileged pinning on the single connection service instance; a parallel implementation would duplicate the pinning and interceptor routing |
| Disabling the web `connection` row in the desktop patch | The row carries the connection browser half into the boot graph; disabling it removed the renderer's wire client and left every client entry pending on `connection` |
| Treating `app://dsh` as a loopback hostname | This couples a connection trust decision to one shell scheme and could classify a `WebApiClient` page as local; the selected IPC carrier is the authoritative fact |
| Giving the desktop carrier its own HTTP server | The shell is intentionally zero-port; remote access is a later milestone with its own listener |

## Consequences

The web GUI and the desktop shell run the identical harness tree and wire contract; a carrier swap touches the connection package's apply, a new node-half entry, a new host package, and the app's own wiring — no protocol change, no new DTO set, no web behavior change (the browser still selects `WebApiClient`). The desktop surface replaces the URL-based web-surface prompt with a desktop-surface prompt, and the model sees no server URL. An assembled cross-carrier regression uses one Harness home across a desktop IPC host, an HTTP Web host, and a restarted desktop host; it requires equal settings-client package sets, configuration namespaces, and provider directories, proves settings and credential changes remain visible in both directions, and rejects any API-key literal in `settings.yaml` rather than `.credentials.yaml`. The costs: a new host package and a new bundle whose invariants and READMEs must be maintained, the carrier's node:http-shaped shim boundary (documented at its single cast point), dev-mode HMR for client plugins is not wired (rebuild + window reload), the sandboxed preload must stay CJS, and the composition test requires a built workspace (it self-skips on a clean tree, the same contract as the keyless snapshot lanes).
