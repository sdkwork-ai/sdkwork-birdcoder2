# Agent Note: PDF 预览读取 pdf.js 6 的文本层契约，并追平 office 系列预览

Status: implemented

[English](2026-09-10-sdkwork-pdf-preview-office-fidelity-round.md) | 中文

## 问题

对 PDF 预览的第一轮商业化回归——对照 docx 与 pptx 兄弟包、也对照任何一个可用的阅读器——发现了六类差距。文本层 CSS 是按 pdf.js 旧版「内联 transform 的 span」写的，而 pdf.js 6 的 `TextLayer` 依靠 `--total-scale-factor` 变量与 viewer 样式表规则来定尺寸与排布字形，本包从未提供，于是选区与复制落不到字形上、`markedContent` 包裹层被当成绝对定位元素破坏布局、旋转后的文本与位图完全对不上。缩略图的缩放比把页面的点宽除以「点转像素」系数而非乘以它，每张缩略图都大了三分之一，再被 `max-width` 压扁而高度不跟随——每一页的纵横比都是变形的。worker 从不发出就绪消息时（Blob URL 被 CSP 拦截、不支持 module worker），boot 永不落定，主体永远停在转圈上。worker 致命失败后，销毁流程以一个不相干的 abort 错误拒绝加载，把刚展示给读者的 worker 解释覆盖掉。适应窗口被钳在 100%，小页面永远填不满窗口，与 office 系列预览不一致。交互面上，加密文档没有解锁入口、没有页码输入、没有 Home/End 与缩放快捷键、没有滚轮缩放、翻页后滚动位置不重置，而缩略图在文档生命周期内持有每一页的光栅。

## 决策

一轮修改，落在既有的 runtime/page/body 划分之内，未引入新依赖：

- **文本层实现 pdf.js 6 的样式表契约。** `renderPdfPage` 在构造 `TextLayer` 前把 `--total-scale-factor` 设为渲染视口的缩放；模块 CSS 镜像官方 viewer 规则——变量推导的字号、`rotate`/`scaleX`/`scale` 变换、`.markedContent { display: contents }`、选区配色——并按官方 CSS 的 `data-main-rotation` 变换，把未旋转的文本层盒子映射到旋转后的页面上。
- **缩略图按页面自身尺寸缩放并回收。** 缩放比从 scale-1 视口（即点尺寸）推导，修正变形；双向 IntersectionObserver 进入视口绘制、离开视口释放光栅，几百页的文档只保留可见页的像素；列表条目加 `content-visibility`。
- **worker 启动必然落定。** 就绪消息、worker 错误、message 错误、持有信号的 abort、以及 15 秒期限都会让 boot 落定；失败的 boot 会终止 worker 并撤销其 Blob URL。致命失败会被记住并作为加载的拒绝原因重新抛出，销毁流程的 abort 错误永远无法覆盖读者的解释；同步的二次 crash 只上报一次。
- **加密文档就地解锁。** `getDocument` 接受可选 `password`；密码失败会渲染表单并用同一份字节重新打开，区分「已锁定」与「密码错误」，「取消」回到锁定态。新的字节身份从一开始就是未解锁的。
- **与 office 系列的交互对齐。** 适应窗口会把小页面放大（移除 100% 上限）；页码输入按 `Enter` 或失焦跳转、`Escape` 或非法输入还原；`Home`/`End` 跳首末页，`Ctrl`/`Cmd` 加 `=`/`-`/`0` 缩放或恢复适应；`Ctrl`/`Cmd` 加滚轮通过原生非被动监听以指针为锚点缩放，按钮缩放以视口中心为锚点——提交期的 layout effect 围绕捕获点重新锚定视口，翻页落在页面顶部并让选中缩略图保持可见。复制处理器会剥离选区中的 PDF 填充空字符。 缩放键直接按键即可——与 office 家族一致——配合 Ctrl/Cmd 也可——与桌面阅读器一致。
- **内联资源表对单个文档每项资源只解码一次**并对外发放副本，中日韩文档不再为同一张字符映射表反复解码。
- **位图原子换帧。** 每一页都在离屏画布上绘制，完成后一次性换入可见画布——缩放与旋转不会让页面闪白，中断的渲染也不会留下撕裂的半页。

## 考虑过的替代方案

**打包 pdf.js 的 viewer 模块（`TextLayerBuilder`、`pdf_viewer.css`）来做文本层。** 可以免费获得官方样式与 `endOfContent` 选区机制，代价是把整个 viewer 模块拖进侧边栏包体——而这只是一份本包可以收进自己模块 CSS 的样式表契约；本包改为复刻其中少数几条规则。

**通过 pdf.js 的 `onPassword` 回调重试密码。** 在 worker 回调里挂一个 React 驱动的输入框，会把 runtime 与组件状态耦合起来；用 `password` 选项重新打开完整字节是无状态、廉价且可端到端测试的。

**用分块渲染抬升光栅上限。** 1670 万像素的上限只在极端缩放下让画面变软；分块渲染面是一个独立工程，也不会改变本轮修复的任何行为。

## 后果

任何页面、无论是否旋转，选区、复制与旋转都落在读者看到的字形上；缩略图保持纵横比，内存跟随可见内容；损坏的 worker 会以读者的那句话响亮失败，而不是转圈或销毁消息；加密文档不离开标签页即可解锁；键盘与滚轮行为与 office 系列一致。六份 spec（body、registration、runtime、page、assets，以及用真实 PDF.js 解析器跑生成夹具、钉住渲染器所依赖的点尺寸与文本提取契约的真实解析集成套件）把每一项新行为钉在仓库逐文件 100% 的覆盖率门禁上。两份 README 的已知限制保留长期缺口：批注与表单域不绘制、没有文内查找、渲染仍是一次一页。
