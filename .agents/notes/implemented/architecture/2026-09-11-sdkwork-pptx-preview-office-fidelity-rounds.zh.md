# Agent Note: PowerPoint 预览按 Office 的方式绘制母版、回退图与自由几何

Status: implemented

[English](2026-09-11-sdkwork-pptx-preview-office-fidelity-rounds.md) | 中文

## 问题

第一版渲染器（[2026-09-10](2026-09-10-sdkwork-pptx-preview-ooxml-renderer.zh.md)）只在继承的背景填充上绘制幻灯片自身的形状，这对默认模板构建的 deck 才算正确。对照真实商务 deck 的两轮回归发现了二十多处差距：渲染器只读第一个幻灯片母版，按节切换设计的 deck 从第二节起就是错的配色与字体；存在于母版与版式上的 logo 条、装饰线、页脚形状完全没有绘制；表格被解析成占位框，因为 `readTable` 在 PresentationML 命名空间里找 DrawingML 的图形元素；图表与 SmartArt——Office 保存时会在 `mc:AlternateContent` 里附带缓存回退图——落到了「不支持」标签上；自由图元（`a:custGeom`）退化为矩形；精确行距（`a:lnSpc/a:spcPts`）被当成无单位倍数渲染，高出数十倍；拉伸的图片填充按 `cover` 裁切而非填满框架；而恶意容器可以驱动无界内存分配，因为 ZIP 读取器没有解压上限。缩略图每页挂载一棵完整元素树，交互上也没有滚轮缩放、没有 Home/End、没有隐藏页标识。

## 决策

两轮修改都落在既有的「解析 → 模型 → CSS 投影」之内，未引入新依赖：

- **文档图按母版解析。** 声明的每个母版都带着自己的主题、颜色映射与文本样式被读取；每个版式经由它自己声明的关系解析到母版（按部件名懒解析并缓存，继承链断裂时回退到第一个母版）。母版与版式上的非占位符形状按 Office 的绘制顺序垫在幻灯片自身形状之前，幻灯片或版式上的 `showMasterSp="0"` 抑制母版层。
- **Office 缓存了什么，预览就画什么。** `mc:AlternateContent` 框绘制其 `mc:Fallback`——Office 为图表、SmartArt 与公式渲染好的缓存图片——位置与尺寸随框。自由几何投影为 CSS `path()` 裁剪，按路径自身的坐标空间缩放（弧段退化为指向终点的直线）。被裁剪的轮廓以第二条色带沿几何描边，而非会裁成碎片的盒边框；连接线按 `a:ln` 的声明长出箭头。
- **文本度量跟随 Office。** 百分比行距按倍数渲染，`spcPts` 按像素高度；`buSzPct` 相对自身 run 取字号而非固定基数；无色的 bullet 取第一个 run 的颜色；波浪/双线/虚线下划线与文字阴影映射到对应的 CSS 形式。
- **表格获得 Office 默认外观。** 当单元格未声明填充且 `tblPr` 要求表头或斑马纹时，解析期就把主题的第一个 accent 烘焙进表头填充、浅色隔行与加粗白色表头文字——渲染模型里没有主题可查。
- **容器有界。** 共享基础的 ZIP 读取器按单条目（256 MB）与整包（512 MB）设解压上限，拒绝虚报的中央目录而不是照单分配。
- **预览可编辑。** 文字编辑即时应用到渲染模型（所见即所得），保存时只重写被触碰的幻灯片 XML、备注部件、关系与内容类型；备注面板常驻可编辑，从未有过备注的 deck 会生成一个最小合法的备注部件。
- **段内跳转可导航。** 指向其他幻灯片的超链接携带 `#slide/N` 标记，主体的委托点击处理器将其转换为翻页；幻灯片部件索引在遍历前先行解析，前向引用同样有效。开口 `arc` 预设沿采样椭圆按描边宽度画出色带，声明 `numCol` 的文本框按栏数分栏。
- **表格解析真实样式。** 演示文稿的 `tableStyles.xml` 部件按样式 id 解析，`readTable` 按 Office 的优先级遍历角色部件（首末行/列、行/列条纹、整表），样式中的主题色相对读取方幻灯片解析；解析出的深色表头把默认色的文字变为白色加粗；没有样式部件的表格保留 accent 启发式。
- **链接与页眉/页脚字段是活的。** 携带 `a:hlinkClick` 的 run 在关系指向 web 或 mail URL 时保留链接——协议白名单把 `javascript:` 之类的目标拦成普通文本——无样式的链接按主题 hlink 颜色着色并加下划线。页脚、日期与页码占位符在 `p:hf` 标志启用时绘制；装饰树逐页折叠，`slidenum` 字段携带每页的真实页位而非生成方缓存的文本，版式自带的同类型占位符会抑制母版的那份。

缩略图轨经一个共享的 IntersectionObserver 懒挂载；Ctrl+滚轮围绕视口中心缩放（原生非被动监听，因为 React 注册的 wheel 处理是被动的）；选中缩略图保持可见；隐藏页带标识；舞台焦点下 `+`/`-` 调整缩放，`0` 回到 `1:1`。解析器在页间让出主线程，大文件不再长时间卡住界面；解析失败与成功一样会释放媒体 Blob URL。

## 考虑过的替代方案

**完整解析 `tableStyles.xml`。** 样式部件的填充/效果矩阵可以精确还原每个内置样式。基于标志的 accent 启发式以极小的解析成本覆盖了默认样式表格的观感，完整的解析器等真正出现差异时再做。

**渲染实时图表与 SmartArt。** 绘制图表模型或图示布局引擎是独立的保真工程；缓存图片正是 Office 自身在降保真场景下显示的内容，而且 deck 一定携带它。

**用 canvas 或 SVG 重写渲染。** 完整的矢量表面能让 custGeom 与描边完全精确，但代价是丢掉无键测试所依赖的「模型 → CSS」纯投影、丢掉可选择且缩放清晰的文本，也丢掉文本帧依赖的分层结构。色带技法与 `path()` 裁剪在既有投影之内买到了同样的轮廓保真。

## 后果

商务 deck 的每一节保住自己的主题，画出自带的模板装饰，显示图表与图标，按 Office 的度量排版文本，并带上可用的页脚、页码与 web 链接。两份 README 的已知限制清单现在如实列出剩余差距：第一个 accent 之外的 `tableStyles.xml` 配色、开口 `arc` 曲线与固定多边形调整值、段内跳转链接、阴影与下划线之外的 WordArt 特效，以及文本适配器。形状阴影按真实的方向、距离、模糊与颜色绘制而非固定近似；媒体字节转成 Blob URL 后即从包缓存中驱逐；编号 bullet 的小写罗马、大写字母与括号形式均精确渲染。覆盖测试钉住了每一项新行为：按母版主题与装饰抑制、回退解包、custGeom 投影、描边色带、箭头、精确行高、百分比 bullet、解压上限、懒加载缩略图轨、滚轮缩放、Home/End 翻页、带协议白名单的超链接解析、`p:hf` 占位符与活页码，以及圆环与弧形条带预设。
