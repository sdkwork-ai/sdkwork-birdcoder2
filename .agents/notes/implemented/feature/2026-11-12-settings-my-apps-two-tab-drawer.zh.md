# Agent Note: 设置菜单的「我的应用」抽屉——两个只读台账

Status: implemented

[English](2026-11-12-settings-my-apps-two-tab-drawer.md) | 中文

## Problem

设置 popover 原来只有一行台账「我的应用部署」，只列出当前用户的 `deploy_app` 记录。把应用发布为开发脚手架模板会产生第二种账号资产——模板列表——而应用里没有任何地方能回答「我发布过哪些模板」，除非打开项目行菜单的模板中心，而模板中心绑定在单个项目目录上。行名承诺的是「部署」，呈现的却是账号下的应用，也完全隐藏了同一账号拥有的模板。

## Decision

该行改名为「我的应用」，打开一个双页签宽弹窗：「我的应用」与「我的应用模板」，两者共用同一对宿主构造客户端（`settings.myDeployments` 席位与 `my-deployments` 行 id 不变）。

- 「我的应用」保留原有只读 `deploy_app` 台账：`apps.list` 的 `USER` 作用域，每页 100 行、五页上限，应用类型分面为本地 OR 芯片，按更新时间倒序。
- 「我的应用模板」读取 `template.appTemplates.list`（接口本身按账号作用域），分页与上限相同，模板状态分面按「已发布优先」排序；行内展示名称、标识、简介、状态、最新语义版本、安装次数与更新时间。
- 最新版本是旁路读取。列表行自身的 `version` 字段是乐观锁计数，因此逐行读取版本页并按 `latestVersionUuid` 匹配（回落为该页首行）。读取经四并发工作池执行，并携带抽屉的 `AbortSignal`，关闭页签会取消剩余读取；读取失败只隐藏该行的版本徽标。
- 两个 panel 元素始终留在 DOM 中，使两个页签的 `aria-controls` 都能解析；但台账在首次访问时才挂载：打开抽屉只读取「我的应用」，模板读取在首次切到该页签时才开始。关闭抽屉会把视图重置回「我的应用」；在抽屉保持打开期间，已访问台账切换后仍保留行、分面选择与版本。
- 两个台账都不写入。发布、安装与模板管理仍在项目行菜单与应用模板中心。模板页签的空态点名行菜单的「发布为模板」，包的 README 记录安装需要项目目录与目标选择，这些由模板中心承担。

## Alternatives considered

- **把模板中心嵌进抽屉。** 否决：发布与安装需要项目目录与目标选择，模板中心本来就能从行菜单打开，且两个 90vw 覆盖层会争用同一层。
- **给模板单独一行 popover。** 否决：账号的部署内容是一份清单，两行近乎相同的台账会让「该去哪看」变成命名谜题。
- **两个台账都预加载。** 否决：为多数操作者不会打开的页签把抽屉打开成本翻倍。
- **把列表行的 `version` 字段当作模板版本。** 否决：那是乐观锁计数，不是语义版本。
- **原样复用模板中心的下载面板。** 否决：它负责安装目标与目标侧栏；抽屉需要的是只读清单，而不是第二个安装表面。
- **用可见页码控件替代加载到上限。** 否决：账号自有集合不大，分页器只增加状态而不改变可达范围；截断说明已把其余部分指向 deployments 控制台。

## Consequences

- 模板页签的成本是一次列表遍历加每个列表一次版本页读取（最多四个并发）。大账号情况记录在包 README 的 Known Limitations 中；没有跨打开的版本缓存，每次抽屉会话都重新读取。
- 分面筛选与版本解析都在本地：超过五页上限的列表不会被加载，版本读取失败或为空时该行仍列出但没有版本徽标。
- 模板页签复用模板中心的状态文案（`templateCenter.download.status.*`），同一列表在两个表面读法一致。
- 抽屉不显示逐页签计数、不提供搜索；两者都作为延后项记录在包 README，而不是半成品。
