# Agent Note: 欠费失败行保留充值入口

Status: implemented

[English](2026-11-23-quota-failure-row-top-up-seat.md) | 中文

## Problem

终止轮次的失败只留下一行持久记录。欠费时该行只有中立的 `message.failure.quota` 文案，可执行的修复却放在 `shell.overlay` 的全局 `shell.quota-notice` 条目里，而它的界面是瞬时的：欠费追加时出现，随后被关闭、被替换或被更新的提示顶掉。回滚到该失败行、或在提示消失后才回到 Session 的读者，只看到一个没有任何出路的失败——尽管同一产品对同一错误码已经知道能修复它的余额页面。本发行版提供的 relay 路由由已登录账号计费，因此「额度用尽」正是需要可重复、持久的充值入口的场景。

## Decision

Chat 的欠费失败行再声明一个修复座位 `conversation.chat.turn-error.top-up`，采用与凭据座位相同的 `TurnErrorRepairOwnerProps` 取值约定：稳定错误码加一段本地化标签。该行渲染中立的欠费文案并追加座位的返回内容；它把 `message.failure.quota.action` 作为标签传入，且不提供 fallback，因此无人注册的座位不追加任何内容。Chat 依旧不持有提供方或计费逻辑：文案仍是同一段本地化片段，手势只出现在有功能贡献它的组合里。

`ui-settings-account` 填充该座位。它的条目响应 `QUOTA` 与 `ACCOUNT_QUOTA`，并通过与设置页和欠费提示相同的 `hooks.account` 可观察对象读取实时账号快照。存在共享原生 Platform 宿主时，它通过既有的 `PlatformPages` 通道申请 `top-up` 页面，Desktop 用户因此落在唯一的原生不透明视图里，打开方的返回还会触发重读；由于该内嵌页面自带登录，即使账号已退出登录，持久失败行仍保留这个手势。在普通浏览器中，它把账号的托管充值 URL 渲染为新标签页链接，且只在已存储凭证、使该页面属于读者自己的账号时给出。页面请求不与该行的生命周期绑定——更新的请求或浏览者自己的返回会撤下它——因此对话重新渲染不会在用户面前关掉页面。

## Alternatives considered

**在全局提示里认领 `QUOTA` 并由提示承载操作。** 该提示本身就是瞬时的，其保持协议属于打开页面的条目；把它变成持久的会让唯一的提示槽变成按失败列出的列表，并重复对话已经渲染的内容。持久记录是失败行，持久入口也应在那里。

**由 Chat 为每个欠费失败渲染固定的充值按钮。** Chat 无法判断耗尽的是已登录产品账号的余额还是第三方 API Key，也不得解析提供方文本来猜测。固定按钮会把 API Key 用户引向无关的账单页。座位把这一资格判断留在拥有账号与计费界面的功能里。

**在路由层把 relay 欠费改写为 `ACCOUNT_QUOTA`，复用现有的提示 Modal。** 这样修复只在提示存活期间可达，正是本次要解决的问题；而且它还会为一种 Modal 文案描述的是账号余额、而非 relay 路由的失败新拉起账号 Modal。行内座位不改动失败分类。

**在 Chat 里复制链接样式。** Chat 不得为功能的入口提供样式或导入；座位渲染普通链接元素，由功能从自己的模块提供样式。文案保留在 Chat 的词典里，因为行拥有那句话。

## Consequences

失败行现在提供与欠费提示相同的修复，在对话显示它的期间一直有效，两个界面共享同一份账号快照与同一个原生页面通道。Desktop 失败行在退出登录后仍保留该手势；未存储凭证的浏览器失败行、以及快照中没有充值 URL 的组合，看到的仍是不变的中立文案，因此没有引入新的死路或错误账单路径。账号包新增一个叶子组件和一个位于 `account/watch` 之后的 `slots.inject` 注册，Chat 新增一个声明的子座位和一个语言键；没有账号插件的组合渲染结果与之前完全一致。

在已登录的产品构建中，第三方 API Key 的欠费仍会得到账号的充值链接，因为该行不知道请求用了哪份凭据。文案不点名提供方，链接指向产品自己的余额界面而非提供方的，因此该入口对自己去往何处仍保持诚实；将来若要按路由区分，就需要在行边界上得到失败请求的提供方，而持久失败记录并不携带它。

座位为空时，行的 `role="status"` 文本保持不变，既有 golden 快照继续有效。链接位于该状态区域内，因此随失败一起被朗读，其焦点描边来自功能自己的样式表。

## Testing

`quota-top-up-action.client.spec.tsx` 覆盖浏览器链接、Desktop 页面请求、两种欠费码、所有拒绝状态，以及尚未加载的快照。`chat-view.client.spec.tsx` 覆盖空座位（中立文本不变）与已填充座位的标签、错误码及其在失败行中的位置，`chat-apply.client.spec.tsx` 钉住声明的子座位。账号 apply 规格断言该条目在有账号访问时存在、无访问时不存在。
