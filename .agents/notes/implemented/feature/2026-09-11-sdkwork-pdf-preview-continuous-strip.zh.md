# Agent Note: PDF 预览以连续、按需绘制的条带呈现文档

Status: implemented

[English](2026-09-11-sdkwork-pdf-preview-continuous-strip.md) | 中文

## 问题

经过保真度（[2026-09-10](../architecture/2026-09-10-sdkwork-pdf-preview-office-fidelity-round.zh.md)）与查找（[2026-09-11](2026-09-11-sdkwork-pdf-preview-find-in-document.zh.md)）两轮之后，条带始终只显示一页：每一次翻页都交换位图、重置滚动、整体重绘。真实的阅读器——以及 PDF 格式自身的阅读模型——把文档呈现为一条读者滚动的连续纵向条带，差距在实际使用中显现：跨页没有阅读连贯性、感知不到文档篇幅、缩放或旋转必须从当前页重绘整个视图。

## 决策

主体把每一页渲染为同一条滚动条带中的一个页框；原来的单页渲染下沉为按页组件：

- **`PageView` 拥有一页。** 每个页框在接近舞台视口时绘制（条带上的 IntersectionObserver，带一个视口高的预取边距；没有该 observer 的环境立即绘制），离开时释放位图与文本片段，因此几百页的文档只保留邻近页的光栅。一个视口同时驱动该页的画布、文本层与查找高亮色带；页面首次绘制后把自己的点尺寸回报给条带，混合幅面的文档自行修正排版。
- **滚动位置即选中页。** 视口中心所在的页框就是当前页；滚动更新共享的分页视图 store，列表高亮、计数与查找流程随之移动。命令则反向工作：列表点击、页码输入、翻页、Home/End 与匹配导航记录一个滚动目标，由下一次提交落到该页顶部。比页面存亡更长的目标（导航途中 worker 死亡）在下一次提交时被丢弃。
- **缩放与旋转保持锚定。** 缩放命令捕获条带的滚动比例，提交期的 layout effect 在重排后的高度上重新施加；旋转交换每个页框的布局尺寸，视口渲染旋转后的位图，各页高亮色带经旋转后视口的矩阵重新映射。
- **查找继承条带。** 查找流程在主体中保留查询、匹配列表与活动索引；每个 `PageView` 只从共享文本索引取自己页面的匹配做色带，高亮、滚动与匹配遍历无需新增状态即可组合。

## 考虑过的替代方案

**虚拟化条带（彻底卸载远端页面）。** 卸载会丢失滚动高度与跨长文档的文本选区；释放光栅但保留页框的方案以每远页一个空画布为代价换取精确排版，与官方查看器的取舍一致。

**所有页框默认使用第 1 页的尺寸直到读取。** 条带正是这样做的（默认值来自第 1 页的视口，之后每页自行修正）；首绘前预读每页尺寸会为首次渲染增加每页一次的 worker 往返。

**保留单页模式作为开关。** 两种渲染模式会让触及舞台的每个特性——缩放锚定、查找跳转、滚动同步——的状态空间翻倍，换来的却是没有任何商业阅读器作为默认提供的模式。

## 后果

读者以预期的方式滚动文档：页面连续流动，计数与列表跟随，缩放与旋转原地保持，查找跳转落到文档任意位置的高亮页。内存跟随可见邻域，因为屏外光栅会释放。已知限制清单记录了剩余项：混合幅面的页面在首次绘制前按第 1 页尺寸排版，且没有双页对开视图。覆盖率在仓库逐文件 100% 门禁上钉住条带：按可见性的逐页绘制与释放、几何回报、滚动推导选区、命令滚动落页顶、跨重排的缩放锚定、被丢弃的过期目标，以及零页文档。
