# Agent Note：IM 链接器作为模式栏快捷入口

Status: implemented

[English](2026-10-20-im-connector-rail-entry.md) | 中文

## 问题

内嵌 IM 插件（`@xmanrui/dsh-im`）在产品导航里先是出现在侧边栏快捷入口栈的末尾、需求大厅下方，之后又以模式栏快捷入口的形式在代码表面打开插件的 `main` 面板。这两种位置都不适合这个表面：侧栏行与产品自己的导航重复，而代码表面面板会把工作区/会话侧栏留在 IM 管理界面旁边。

产品希望 IM 表面像应用商店一样：最左侧一个图标，打开后是由图标栏和 IM 内容组成的完整页面——不显示工作区侧栏——名称是 **IM链接器** 而不是插件面板文案 IM机器人。产品还要求渠道未链接、网关不可达时仍然完整显示管理界面；连接状态属于面板内部的内容，而不是替代界面。

该插件是链接进仓库的 git 子模块，其提交的 `lib/*.js` 按原样发布（见[内置 IM 接入说明](../architecture/2026-10-09-built-in-im-plugin-via-git-submodule.zh.md)），因此宿主不能通过修改插件来重命名或重新注册插件自己的行或表面。但它发布了 `dshImClient` v1 服务，支持宿主构建完整的管理面板。

## 决策

- 模式栏新增 `mode.rail.panel`：由 ui-sdkwork-app-modes 声明的 root 作用域 list 席位，渲染在 `mode.rail.settings` 正上方、模式条目组之外。每个快捷入口自己负责外观、图标、文案与点击，以 owner props 接收框架的 `activeMode`，并通过 layout 服务打开自己的表面。
- `im` 成为框架词表中的新应用模式。`ui-sdkwork-im-connector` 为它注册 keyed `mode.page`，在插件页原本的表面几何（可滚动的全高框架 + 1080px 内容列）中通过 `dshImClient.render()` 渲染插件面板。因此框架只显示图标栏与页面，不显示工作区侧栏——与应用商店及其他模式栏模式完全一致。
- 模式页与渠道连接状态无关。无论账号是否已绑定、机器人是否在运行、网关是否可达，页面都会挂载并渲染完整的管理面板；面板自己的卡片、扫码流程与状态文案说明失败原因。链接器不会用错误状态替代界面。
- `ui-sdkwork-im-connector` 以插件公开的面板 id（`xmanrui-dsh-im`）在设置上方注册模式栏快捷入口。框架的 `activeMode` 为 `im` 时入口绘制选中态，点击则把框架切到 `im`。
- 快捷入口的 list id 就是侧栏过滤所用的面板 id：ui-sidebar 会省略同时出现在 `mode.rail.panel` 中的 `sidebar.panellist` 条目，因此插件自己的行消失而无需编辑插件。面板主体、其设置分区与插件详情操作保持不变。
- 快捷入口与模式页都是插件 `dshImClient` v1 服务的投影：一个子级注入持有两处注册，因此没有组合 IM 插件的部署不会出现死图标，插件卸载时产品导航随面板一起移除。

## 备选方案

**保留插件的 `main` 面板，只为它隐藏侧栏。** 框架的 `sidebarVisible` 是当前表面的纯函数；为单个主面板隐藏侧栏需要再引入一项导航事实，并让整个框架订阅面板选择，而框架刻意避免这样。应用商店式的表面恰好就是模式页，因此模式是更小的改动。

**一开始就把 IM 面板做成模式页。** 第一版否决了它，因为插件详情页也需要到达该面板，而且模式会引入 `AppModeId`、页面与窗口标题词汇。产品后来要求应用商店式的组合（不显示工作区侧栏），而只有模式页能提供；`mode.rail.panel` 快捷入口让入口仍在设置上方而不进入模式组。

**修改 dsh-im 子模块以移动或重命名它的行。** 内置 IM 决策把它固定为不修改的链接产物，pin 可以在不合并 fork 的情况下前进；修改它等于把插件分叉，而且每次同步都要重新构建并重新发布它提交的浏览器包。产品导航属于宿主。

**在 ui-sidebar 里硬编码要隐藏的 id。** 一个 id 加一个过滤列表代码更少，但会把第三方产品 id 埋进上游合并的外壳，而且下一个模式栏快捷入口还要再改同一个文件。现在的过滤读取模式栏席位自己的注册列表，规则是通用的。

**把 `sidebar.panellist` 整体迁到模式栏。** 那会迁移所有组合中的所有全局面板——包括开关打开时的上游任务管理器与插件管理器——并且重新安置一项上游契约。产品要的是这个面板的快捷入口，不是一次通用迁移。

**连插件的设置分区一起重命名或 shadow。** 该分区是插件自己的注册；shadow 它会重复其面板接线，并破坏可选桌面接入的 `setSettingsVisible(false)` 契约。插件保留自己的文案，模式栏入口与模式页标题承载产品名称。

## 后果

- IM 面板现在是一个完整应用表面：打开期间不渲染工作区/会话侧栏；切回任意模式即恢复侧栏。
- 链接器的页面始终显示完整管理界面；IM SDK 连接失败或缺失由面板内部报告，而不是变成页面级错误。完全加载不到 IM 插件的宿主没有面板服务，因此快捷入口与页面会直接不出现，而不是变成死图标。
- 插件自己的 `main` 面板与插件详情操作仍然注册；它们是一条单独的导航路径，仍会在代码表面打开面板并显示侧栏。
- 侧栏面板列表不再提供 IM 面板，而模式栏快捷入口提供；`sidebar.panellist` 记录了“由模式栏快捷入口接管的行只由该入口列出”的契约。
- `im` 加入框架模式词表与窗口标题字典。若出现第二个 IM 表面，它们会复用该页面。
- 插件自己的文案（IM机器人 / IM bots）仍保留在设置分区与插件详情操作中；模式栏入口、模式页标题与窗口标题使用链接器名称。

## 验证

`ui-sdkwork-im-connector` 的规格钉住两处注册跟随 `dshImClient` 服务（存在、缺失、服务撤销、插件卸载）、模式切换、`im` 页面渲染服务返回的元素、双语文案，以及入口的选中态与悬停标签行为。app-modes 的规格钉住新席位位于模式组之外、设置图标正上方，并接收框架的 activeMode。ui-sidebar 的面板列表规格钉住被模式栏接管的面板行被过滤与恢复。common-app-header 的规格覆盖 `im` 窗口标题。真实组装浏览器验证显示该模式页只有图标栏、没有工作区侧栏，并且可以从其他模式打开面板。
