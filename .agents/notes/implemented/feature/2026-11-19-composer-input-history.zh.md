# Agent Note: 输入框输入历史

Status: implemented

[English](2026-11-19-composer-input-history.md) | 中文

## 问题

Host 接受一条消息后，输入框立即丢弃其文本；想再次使用之前的措辞，只能回到会话记录里查找。分叉希望聊天输入框具备 shell 风格的 ↑/↓ 回溯：默认按会话，可选项目或全局，并支持可配置的保留期，同时不把账本发送给 Host 或模型。

## 决定

- 由 fork 自有的客户端插件 `packages/client/ui-sdkwork-input-history` 承担整个能力：浏览器本地账本、手势控制器，以及一个用于范围、保留期与清除的 `settings.section` 设置页。
- conversation 包在普通消息被 Host 接受并结算后发出一个类型事件 `conversation/input-accepted`，并在输入框卡片上标记 `data-composer-session-id`。两者都是仅面向 UI 的扩展点；命令提交不会触发该事件。
- 手势通过 `ctx.shortcuts.observeFixedInput` 在输入框所有本地处理之后观察按键，因此被 `/` 或 `@` 菜单消费的键不会进入历史。只有草稿为空或光标位于所询问的边缘时才开始一次新的回溯；记录显示后，只有从文档边缘按下才会继续回溯，在记录内部按下仍用于移动光标。在最新一条之后继续按 ↓ 会恢复被回溯打断的草稿。
- 每个条目携带发送它的会话，以及该会话工作目录产生的项目键。范围在读取时解析，因此切换范围不丢历史。保留期（默认 30 天，1–365 天）在每次读写、启动时以及每小时清扫中执行。存储使用 `localStorage`（`dsh.inputHistory.v1`），最多 500 条、总计 500,000 字符，使整个文档远低于浏览器配额。

## 备选方案

**从会话事件重建历史。** 每个会话本就保存用户消息，但只有被保留的会话拥有事件窗口，项目/全局切片无从获得，而且客户端还要解析由 `ui-conversation` 装配器拥有的会话记录。在接受时捕获是有界、私密且范围一致的。

**把 ↑/↓ 注册为快捷键命令。** 快捷键注册表会校验默认绑定并把裸方向键视为保留输入，而且它的分发无法表达“仅当没有本地处理器消费此键”。固定键盘观察在输入框自身处理器之后运行，并能拿到实时 DOM 目标与 `defaultPrevented`。

**把账本存到 Host。** 账本是没有任何模型可见影响的呈现状态；Host 存储会引入需求并未要求的线路接口与跨设备语义。浏览器本地存储与现有草稿、模式栏布局的做法一致。

## 后果

- 该能力按浏览器 profile 生效：不同步、不跨设备回溯，清除站点数据即清除。多个标签页之间不同步账本，最后写入者生效。账本不按登录账号分区，登出也不会清除，因此共享 profile 切换账号前需手动清除。
- 记录从插件启用时开始；更早发送的消息不会从会话记录回填。
- 事件必须保持在 Host 接受之后发出，且绝不能携带命令提交；观察者异常会被隔离，不得中断结算。
- `ui-conversation` 的扩展点是跨上游合并维护的 fork 分歧：事件声明、hub 发事件与输入框属性必须一起移动。

## 测试

`tests/` 覆盖账本（默认值、范围读取、去重、500 条上限、读取/启动/定时清扫时的保留期、持久化与损坏存储）、手势（光标边缘、菜单/修饰键/输入法保护、范围回溯、草稿恢复、关闭状态）、真实 Lexical 输入框上的按键路由、设置页渲染，以及插件在真实槽位注册表与事件总线上的注册和销毁。
