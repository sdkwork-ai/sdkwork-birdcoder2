# Agent Note: 技能管理：组合级目录与加法式标签条成员关系

Status: implemented

[English](2026-09-18-skill-manager-global-catalog-and-additive-strip.md) | 中文

## Problem

「技能」设置页与新建会话标签条建立在一个共同假设之上——目录是「某个会话」的目录——而这个假设让该功能丢掉了它原本想要的大部分价值。

由它引出两处失败。第一，该页无法在工作区尚未选定前打开：宿主从会话的项目根解析目录，因此想看看产品到底自带哪些技能的读者必须先建一个会话，而该页只能给出一条说明文字、什么也展示不了。更严重的是第二点，该页只能对标签条做**减法**。标签条的成员关系来自 `ui-sdkwork-app-modes` 拥有的构建期场景表，而该页只暴露了一份 `hiddenSceneTags` 列表，因此 13 个 `dsh-*` 包、预设 `customSkillDirs` 条目以及每一个用户级技能，都没有任何起作用的开关——读者看到某一行是场景表从未挑中的技能时，那个控件只可能处于关闭态。一个列出技能、却不提供任何方式去推荐它的设置页不是管理器，而是一个带着死控件的查看器。

两处失败之下还藏着第三处、更安静的失败：宿主先以 `isUserInvocable` 过滤再作答，因此 `skills.list` 从来不是一份中立清单，每个消费者都继承了这个假设——只有用户能输入的技能才是值得关注的技能。

## Decision

三项改动，各自拆掉其中一个假设。

### 目录变为双寻址

`skills.list` 接受 `sessionId` 或 `scope: 'all'` 两者之一。给定 `sessionId` 时，它照旧回答该会话的项目级目录。给定 `scope: 'all'` 时，它回答**组合级清单**：所有不依赖工作目录的根。

其机制是注册表自身的根选择，而不是另开一条代码路径。`skillFilesystem.roots(cwd)` 只在设置了 `includeDefaultRoots` **且** `cwd` 有定义时才挂载项目根；没有 `cwd` 时，自定义、用户级与内置根仍会挂载。因此全局视图是向同一个注册表提出一个它本就能回答的问题，而该页为了得到想要的答案绝不臆造 cwd。`SkillEntry` 新增 `source` 与 `provider`，让该页能说出某一行从何而来，而不是让读者去猜；宿主在该边界把注册表开放的 `source` 字符串收敛进闭合的 `SkillEntrySource` 词表（`project` / `custom` / `user` / `bundled` / `runtime` / `unknown`）。

### 目录成为中立清单

`.filter(isUserInvocable)` 从宿主移到消费边界上。`skills.list` 现在也返回仅模型可调用的技能，每个消费者各自过滤自己可以提供的部分：`ui-skill` 中的 `/` 菜单与引用解析器按 `userInvocable` 过滤，面向模型的目录照旧按 `modelInvocable` 过滤。因此该页能列出并开关一切，而这正是管理器页面该做的事。

### 标签条成员关系是加法式的，且增量由用户掌握

第三个偏好字段 `pinnedSceneTags` 加入 `ui-sdkwork-skills` 段的 `disabledSkills` 与 `hiddenSceneTags` 之列。成员关系从 `场景表 − hidden` 变为 `场景表 − hidden + pinned`。

场景表保持原样：它仍是提供默认座位的构建期产品决策。这层叠加是对它的集合运算，而非替代——pin 的技能获得一枚标签但不暂存场景，hide 的技能也仍可完整地从 `/` 菜单使用。该页的开关刻意做成方向中立的（「显示 / 不显示」）：它把自己的场景表成员关系作为 `sceneDefault` 参数向下传递，由写入路径选择相符的字段。因此把某个场景表技能重新打开，会**清掉**它的 `hiddenSceneTags` 条目而不是添加一枚冗余 pin；存储段因此永不累积死条目，且每次写入都是纯设置写入，而不是对一个反向标志取反。

两份列表刻意**不**约束为互斥，store 也不强制其互斥：较早的文档、手工编辑，或两次写入竞态，都可能让同一个名字出现在两边。此时**hide 胜**。该优先级只在**一处**计算——即 `skillPreferences` 服务发布的 `hidden` 集合——由标签条逐标签消费，因此不存在第二份实现可供漂移。

### 标签条的名字文法即公开技能文法

token 匹配器原为 `/\/birdcoder-[a-z0-9-]+ ?/g`，硬编码了 fork 自己的包前缀。pin 一个 `dsh-*`、预设或用户级技能，会渲染出一枚标签文字正确、点击却落不到任何地方的标签，因为替换模式写入不认识自己的 token。现在它是开放 Agent Skills 文法 `/\/[a-z0-9]+(?:-[a-z0-9]+)* ?/`，另加一个尾部残缺匹配器，使输入到一半的 token 仍被替换而非重复拼接。追加的 pin 以 `/<skill>` 取自技能自身名字，因此标签条无需为它并非随之构建的技能准备本地化别名。

## Alternatives considered

**给 `skills.list` 加一个 `cwd` 参数，让该页传工作区根。** 这正是旧限制的措辞所暗示的做法，而它恰好在最关键的情形上失败：工作区尚未选定之前**没有** cwd 可传，所以该页在新用户最想浏览的那一刻依然是空的。它还会让客户端负责选择根，而这是一个宿主组合事实。

**保留宿主侧的 `isUserInvocable` 过滤，另加一个仅模型的列表调用。** 两次调用、两种形状，意味着两份缓存、两条失败路径，以及一个必须合并它们的页面——而合并处正是来源或提供方不匹配最容易被藏住的地方。把过滤移到边界上则保持一次调用、一种形状，且每个消费者的过滤都是政策真正生效之处的一行代码。

**把 `pinnedSceneTags` 作为主字段，由它推导出 `hiddenSceneTags`，只保留一份列表。** 单份列表无法同时表达「这个场景表座位是关的」和「这个非座位是开的」，因为两者相对的是不同的默认值。合并它们将被迫要么把每个场景表名字都写进文档以表示「未改动」，要么失去关掉某个场景座位的能力。

**强制两份列表互斥——每次写入总是把名字从另一份里移除。** 看起来更整洁，但它把一次写入变成了两次写入的序列，因此两次之间失败会让文档停在那个不变量本该防止的状态；在竞态下，它还会让结果取决于写入顺序。定义「hide 胜」的代价是一个 `Set`，且没有中间态。

**保留 `birdcoder-` token 前缀，对 pin 标签做特例处理。** 该前缀曾是真正的不变量，但那是**场景表**的不变量，不是标签条的：标签条只需要识别它自己写下的 token。把匹配器绑到场景表的包前缀上，使 pin 在结构上不可能实现；公开文法才是标签条真正消费的东西。

## Consequences

该页从冷启动即可用，且它的开关对渲染出的每一行都起作用，这正是重点所在。代价是目录读取现在有两种寻址模式，且 `skills.list` 的每个消费者都必须按自己关心的那个轴过滤——过滤是移动了，不是消失了；`ui-skill` 正是这次改动必须找出并更新的第二个消费者（它那 11 个失败用例就是宿主侧过滤一直在承重的第一份证据）。

客户端 store 中的 `SkillCatalogSource` 与宿主中的 `SkillEntrySource` 是同一套闭合词表的两种拼写，因为客户端不得导入宿主类型。这份重复是刻意的，但它确实是真实的耦合：新增一个来源类别意味着两处拼写与成对的 `row.source.*` 字典条目必须一起改动，而宿主测试的来源映射用例会最先变红。另一种做法——客户端导入宿主联合——是用一条当前并不存在的包图边来换取五行重复。

`scope: 'all'` 是按组合而非按最近项目：它展示不依赖工作区的内容，而不为用户尚未打开的项目臆造一个 cwd。想要某个特定项目的技能的读者仍然去打开它。

技能消失后其 pin 仍会渲染。标签条仅凭偏好列表追加 pin，并不拿它去校验已获取的目录，因此被移除的技能会留下一枚死标签，直到用户在该页清掉它。另一种做法是在标签条的渲染路径里做一次目录获取，那会把一次 Remote 调用与一个失败态塞到一枚推荐标签之下；而该页正是陈旧条目可见、可删之处，所以也正是在那里被删除。

## Testing

- `packages/api/session-controller/tests/session-skills.host.spec.ts` —— 双寻址（`scope: 'all'` 与 `sessionId`）、向闭合词表的来源映射、注册表缺失时的失败，以及作为有意为之的已交付行为：仅模型可调用的技能会出现在列表中。
- `packages/client/ui-sdkwork-skills/tests/skills-section.client.spec.tsx` —— 每一行都带有可用的推荐开关，包括非场景表的行；方向中立的开关会写入与其默认值相符的字段；以及五种目录状态。
- `packages/client/ui-sdkwork-skills/tests/skill-preferences.client.spec.ts` —— `hidden` 集合随快照一起发布，使优先级不在下游重算。
- `packages/client/ui-sdkwork-app-modes/tests/scene-skill-tags.client.spec.tsx` —— pin 的技能会渲染、hide 胜过 pin，以及放宽后的 token 文法能往返处理非 `birdcoder-` 名字。
- `packages/client/ui-skill/tests/browser-plugin.client.spec.ts` —— 边界过滤：仅模型可调用的技能不出现在 `/` 菜单候选中，也不出现在引用词表里。
