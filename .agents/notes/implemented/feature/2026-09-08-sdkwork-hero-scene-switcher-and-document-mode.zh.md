# Agent Note: 新建会话英雄区获得场景切换器与文档模式占位页

Status: implemented

[English](2026-09-08-sdkwork-hero-scene-switcher-and-document-mode.md) | 中文

## 问题

新建会话英雄区此前只有一条路径：每个新会话都从代码工作台开始，想用媒体创作表面就得知道去模式栏里找。产品设计要求在英雄区标题下方放一个场景切换器——代码开发、媒体创作、文档生成——选中场景后用户仍停留在对话界面，只有提交第一条消息后框架才前往该场景的表面。当时标题下方没有席位，文档生成没有对应的框架表面，也没有任何接缝把英雄区的选择与提交时刻连起来。

## 决策

`ui-conversation` 声明一个新的 root 作用域席位 `conversation.hero.modeSwitch`，`HeroShell` 把它渲染在标题正下方（工作区行之前）；无注册者时席位为空，因此不含 fork 插件的组合保持上游的英雄区形状。

`ui-sdkwork-app-modes` 用 `HeroModeSwitch` 占据该席位：按展示顺序覆盖三个场景的胶囊组（`HERO_SWITCH_MODES`：code、video、document）。点击胶囊把场景暂存进插件自有的可观察 store（`createHeroSceneStore`），并停留在当前对话界面——胶囊绝不触碰框架模式。受门控的场景在未登录时暂存即弹出登录浮层，让要求在用户还在英雄区时就暴露出来。暂存场景就是胶囊的选中态（实心字形、反色胶囊样式、`aria-pressed`），store 实例随插件存活，因此暂存选择能跨过英雄区的挂载周期。

提交是跳转的触发器：插件的 apply 世界订阅会话列表，观察当前会话的 `blank` 位。`blank → 非blank` 的翻转——第一条消息落地——消费一个非代码暂存，并经模式栏的认证通道（`requestAuthenticatedMode` 调 `ctx.layout.setMode`）切换框架：未登录的视频提交仍会跳转并打开登录浮层。触发器是“翻转”而非“行非空白”，因此已是活跃会话、或其它插件向新会话派发提示词，都不会误消费暂存；当前会话变化时基线重新武装，暂存被消费后重置为代码。

文档生成获得真实目的地：`document` id 加入框架的 `AppModeId` 联合类型与本包的基础模式（`BASE_MODES`；因 `MODE_ORDER` 不分发而不出现在模式栏——与 `work` 同样的处理），并配有 keyed 的 `mode.page` 占位页（“页面建设中”）与文档字形。共享应用头部记录该模式的标题（`mode.document`），因为其标题键映射是对全部非代码模式的穷举记录。

暂存的场景同时决定输入卡片下方（`conversation.composer.dock`，id `hero-scene-skills`，英雄卡片同样渲染该位）的 skill 标签条：标签默认全部展开、居中换行排布，每个标签对应该场景的一个内置 skill（`SCENE_SKILLS`），全部是仓库 `.agents/skills` 项目根下、符合开放 Agent Skills 规范的 `birdcoder-*` SKILL.md 包。点击标签会落下与 '/' 菜单选中完全相同的 `/name ` 字面量——写入走会话的公共 `inputActions.setDraft`，采用替换模式：草稿中已有的 BirdCoder skill 令牌（完整令牌，或仍在输入的尾部残缺令牌）会先被剥除，再以单个空格连接落上新令牌，因此一份草稿同时只携带一个 BirdCoder skill——宿主的 skill 前置步骤对标签选中与手输选中一视同仁，chip 外观仍是编辑器的扫描派生装饰。composer-dock 席位是 session 作用域，直接把输入机交给标签条（早先的布置试过英雄区席位：先放在输入卡片上方、被卡片裁切，后又放到标题下方、与胶囊 chrome 争抢）；标签条自 blank 阶段到首次提交前渲染于卡片下方，会话进入活跃阶段后随英雄区消失——放在卡片下方而非上方，输入框顶部的工具区不与标签交互冲突。ui-conversation 对本包保持纯类型依赖：不再有运行时跨插件导入，因此无需 `dsh.client.external` 行。

## 曾考虑的替代方案

**点击胶囊立即切换框架（模式栏的语义）。** 被产品设计否决：用户选中场景是为了塑形即将输入的对话，跳转必须等提交；立即跳转还会丢掉草稿上下文。

**把胶囊硬编码进 `HeroShell`。** 否决：英雄区 chrome 是通用表面，模式关注点属于模式功能模块；席位让 ui-conversation 不携带 fork 的模式词汇，也让不含插件的组合保持上游形状。

**用框架 store 持有暂存。** 否决：slot store 按条目挂载实例化，暂存会在英雄区卸载（第一次提交）时恰好被遗忘；插件自有的普通可观察对象用三个方法跨过挂载周期，不需要 store 机器。

**直接观察输入框的提交动作。** 否决：提交路径由 ui-conversation 持有，没有观察接缝；会话列表的 blank 翻转与英雄区/输入框阶段选择读的是同一事实，且经既有服务即可到达插件。

**让标签条直接切换框架模式，或远程拉取 skill 目录。** 否决：标签是草稿写入而非导航——跳转时机归暂存场景所有；'/' 菜单选中的纯文本契约（线上是 `/name `、宿主侧解析）已经覆盖了发现语义，标签复用它而不是再发明第二种 skill 引用形式。

## 后果

英雄区在标题下方展示三个场景；选中媒体创作或文档生成后用户停留在对话界面且胶囊高亮，提交第一条消息后框架落在该场景的模式页（未登录的视频打开登录浮层），消息同时在后台会话中流式进行。回到代码时恢复的是活跃会话而非英雄区。胶囊下方的标签条始终反映暂存场景，点击标签即像 '/' 菜单一样把 `/name ` 落入草稿——并替换先前暂存的 skill 令牌。覆盖固定了形状：`hero-mode-switch.client.spec.tsx`（面板顺序、按场景的标签、常驻暂存、暂存不跳转、暂存时门控、替换式草稿写入）、`apply.client.spec.ts`（席位注册、观察者的翻转跳转与消费、会话切换重武装、拆卸）、`mode-page.client.spec.tsx`（文档占位页），以及会话骨架规格（席位位于标题与主体之间）。
