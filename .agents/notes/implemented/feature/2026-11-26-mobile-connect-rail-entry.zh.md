# Agent Note: 消息中心上方的移动端连接快捷入口

Status: implemented

[English](2026-11-26-mobile-connect-rail-entry.md) | 中文

## 问题

客户端缺少一条从桌面端通往产品移动端的入口：Flutter App 与微信小程序是各自独立的应用，工作区里没有任何地方提供它们的扫码目标；产品还希望有一处可见位置记录「本机是否对移动端连接开放」。底部快捷入口区本来就是产品级入口所在——[IM 连接器](2026-10-20-im-connector-rail-entry.zh.md)所用的 `mode.rail.panel` 席位渲染在设置上方，消息中心的 order 是 20——因此新入口应紧贴消息中心上方。

产品给出的参照是一个 hover 弹层：两个扫码目标、一个二维码，以及一个「允许移动设备远程连接」开关。

## 决定

- 新增包 `@deepseek-ai/dsh-client-ui-sdkwork-mobile-connect`，在 `mode.rail.panel` 以 order 15 注册一个图标格：IM 连接器（10）、本入口（15）、消息中心（20）、设置。该图标格只负责展示——它不选中任何中栏面板，因此永远不会与面板快捷入口的选中态争用——并复用共享的 `remote-connection-outline` 字形，而不是新增图形。
- hover 时在 140ms 停留后打开 compact `HoverCard`；点击时在 `Modal` 中打开同一个卡片主体。两种宿主共用同一个组件，因为只有 hover 的入口对键盘与触屏都不可达（hover 卡本身也忽略触屏指针）。
- 卡片由产品的两个扫码目标加一个持久开关组成：目标取自命名空间的 `appDownloadUrl` 与 `miniProgramUrl`，开关是 `remoteAccessEnabled`。三者都是 `ui-sdkwork-mobile-connect` 设置命名空间的 volatile 字段，经由 `ctx.configForms` 读写，因此两个窗口与刷新后的页面看到同一份值。
- Host 半只为声明该命名空间（`Config`）并关闭其自动生成的设置页（`settings.configure({ auto: false })`）：卡片是唯一读取它的界面，再生成一份形状不同的副本没有意义。
- 扫码底板是固定的浅色实物。二维码编码器需要具体颜色，因此这对颜色与编码器一起放在组件里，并以两个局部属性传给样式表；底板不随主题变化，符号也永不以反色绘制。在 hover 卡内部，卡片把交给 `SegmentedTabs` 与 `Switch` 的语义别名（`--dsw-alias-label-*`、`--dsw-alias-bg-module-platform`、`--dsw-alias-bg-layer-3`、`--dsw-alias-border-l3`）重映射到 hover-card 材质上，让共享控件保持自己的几何、角色与键盘行为。
- 状态：分区同步期间只显示 spinner；所选目标非空时显示二维码；目标为空或命名空间未部署时显示未配置提示（并说明填写部署地址即可）；开关写入被拒时显示一行失败提示。分区不可写时开关自身禁用。

## 备选方案

**把入口并入消息中心的卡片。** 消息中心已经占有一个图标格和一个未读徽标；让同一个图标再承担一项无关能力，会让一个图标对应两件事，并把设备入口藏在通知入口之后。

**复用远程连接的设置分区而不新增快捷入口。** 设置里已经提供对外地址、二维码登录票据与配对审批，但那些是设置对话框内的 owner 配置面。需求中的入口是从 rail 一眼扫码，因此它是独立的快捷入口，不打开任何设置分区。

**现在就让「允许移动设备远程连接」在 Host 侧生效。** 开关今天只是持久化并渲染；让它真正门控远程访问，需要 Host 的 remote access 准入路径读取同一个字段。在该路径存在之前先做 UI 门控，等于宣称 Host 并未提供的保证，并且会在产品尚未界定范围时改变远程访问行为。字段就是那条接缝，包 README 记录了这处差距。

**为图标格另画一个「显示器 + 手机」字形。** 产品给的参照里就是它，但图标契约要求新字形先经设计批准，而现有的 `remote-connection-outline` 已经表达了同一含义；复用让这次改动留在共享图形策略之内。

**只做 hover 显示。** 已否决：hover 对键盘用户不可用，也会被触屏指针忽略，因此弹窗路径才是让同一批扫码目标与开关对所有人都可达的方式。

## 影响

- 开关是持久偏好，还不是执行点。关闭它会改变保存的值、渲染出的开关，以及「谁可以连接」之外的其他一切。包 README 的「已知限制与后续工作」与该字段自身的文档说明了这一点，强制生效落在 Host 的准入路径上。
- 扫码目标是部署配置。目标为空时渲染未配置状态，而不是为一个猜测的页面画二维码；修改目标意味着改写 profile 条目——该命名空间刻意不暴露自动生成的设置页。
- rail 位置固定为 15。面板快捷入口不属于 rail 的自定义对话框，因此用户既不能移动也不能隐藏该图标格；移动它就是修改这条注册。
- 扫码配色是本包唯一有意绕开主题别名的地方。它不是样式表里的字面量，因此主题的颜色门禁依然成立，且底板在浅色与深色主题下渲染一致。
- `qrcode.react` 被私有打包进本包的浏览器分块；客户端其他部分无法经由本包导入它。

## 验证

三个 spec 文件（16 个用例）钉住该界面：卡片的扫码目标、页签切换、二维码可访问名称、开关写入与其失败提示、加载与未配置状态、弹窗材质；rail 图标的标签、hover 卡、点击弹窗，以及分区未解析时不展示目标；apply 接线的 order 15、注入面、写入失败收容与卸载。邻接包（ui-primitives、ui-sdkwork-app-modes、ui-sdkwork-message-center、ui-sdkwork-im-connector）在注册新行后全部通过，主题样式门禁对本包无任何发现。
