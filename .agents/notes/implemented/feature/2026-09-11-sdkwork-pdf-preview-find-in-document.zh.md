# Agent Note: PDF 预览支持全文查找并在画布上高亮匹配

Status: implemented

[English](2026-09-11-sdkwork-pdf-preview-find-in-document.md) | 中文

## 问题

保真度回归（[2026-09-10](../architecture/2026-09-10-sdkwork-pdf-preview-office-fidelity-round.zh.md)）之后，阅读器剩余的最大缺口是文内查找：office 系列预览的读者可以选中与复制文本，但想在百页文档里找一个词的读者没有输入框、没有匹配计数、也没有跳到命中处的办法。文本层让文字在 DOM 里真实存在，却没有任何东西扫描它们，也没有任何东西标出命中位置。

## 决策

查找落在新模块 `pdf/search.ts` 中，不引入新依赖，并接入既有主体：

- **每个打开的文档一个懒文本索引。** `PdfTextIndex` 经 PDF.js 读取每页文本内容一次并缓存，因此首个查询只为未读页付出 worker 往返，之后每次细化查询都不再重复读取。新的字节身份会建立新索引并清空查找。
- **匹配建立在拼接后的片段文本上。** 每页的文本片段忽略大小写拼接；每个命中记录其所在页、所属片段与字符区间，因此匹配按跨页阅读顺序报告，跨越样式边界的命中锚定在容纳其首字符的片段上。
- **高亮是经渲染视口映射的色带。** `matchRect` 把匹配的字符比例区间经视口的「用户空间 → 视口」矩阵映射，映射色带的两个对角——基线两端与上缘线——因此色带在查看器支持的任意 90° 旋转与任意缩放下都落在字形上。色带位于位图之上、可选文本 span 之下，`pointer-events: none`，选区与复制行为与之前完全一致；当前匹配的着色强于页内其余匹配。
- **工具栏承载整个流程。** 查找框随输入即扫；计数显示 `{index} / {total}` 或「没有匹配」；前后按钮按阅读顺序遍历匹配并首尾回绕；激活另一页上的匹配会打开该页，并像每一次翻页一样落在页面顶部。`Escape` 清空查询，`Enter` 前进，`Shift+Enter` 后退，按钮通过自身标签与活动的匹配计数向辅助技术报告。

主体只持有查询、匹配与活动索引三项查找状态；其余全部派生——高亮色带由匹配、选中页的缓存文本片段与最近一次渲染的视口变换重算，因此旋转与缩放会让色带跟随页面。

## 考虑过的替代方案

**复用 PDF.js 的 find controller 与 `TextHighlighter`。** 官方机制提供逐字符精确高亮，但它经事件总线与完整 viewer 耦合，依赖自己的页面注册表，会把 viewer 模块拖进侧边栏包体。色带方案在本包架构内覆盖了读者的需求；若比例色带日后被读出不够精确，字符级拆分 span 仍可随时加上。

**只搜索当前页。** 不做全文扫描的高亮几乎零成本，但读者的问题是「这份文档的哪里」——页内答案仍要读者手动翻页，这正是本功能要弥合的缺口。

**经 PDF.js 的规范化做变音符不敏感匹配。** 官方查找器用规范化文本内容折叠重音；我们的夹具语料尚未需要它，折叠可以在 `PdfTextIndex` 内部加入而不触及任何调用方。

## 后果

读者可以在文档任何位置查找短语，看到计数，按阅读顺序遍历命中，并在任意缩放与旋转下落到命中页、命中处高亮在画布上。查找状态随新的字节身份重置；不可读的页面让文档安静地不可查找而非抛错；扫描可取消，输入细化不会互相竞争。覆盖率在仓库逐文件 100% 门禁上钉住匹配表（大小写折叠、多片段页、跨界钳制、跨页顺序、abort、缓存）、色带几何（恒等、旋转、空串情形）与主体流程（扫描、计数、回绕、跨页跳转、Escape、不可读页静默）。已知限制清单现在记录查找的剩余项：无变音符折叠、跨样式边界仅首片段高亮。
