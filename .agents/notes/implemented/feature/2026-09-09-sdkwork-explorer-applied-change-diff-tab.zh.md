# Agent Note: 探索器的已应用变更 diff 标签页——编辑/写入文件链接的落点

Status: implemented

[English](2026-09-09-sdkwork-explorer-applied-change-diff-tab.md) | 中文

## 问题

点击编辑/写入工具行里的文件路径，打开的是文件当前内容的普通只读标签页（或者把路径交给操作系统）。变更本身——这次调用新增和删除了什么——只藏在折叠行的 diff 卡片里，正文上限八行。复核一次已应用的变更，意味着展开一张小卡片，或者盯着变更后的全文用眼睛重建差异。更糟的是，探索器的 Monaco 内核本来也渲染不出更完整的视图：它的启动回调在编辑器宿主元素缺失时直接放弃，而预启动回退分支恰恰不渲染这个元素——内核因此永远不启动，每个文件标签页都停在轻量列表上，可编辑的源码标签页实际上无法编辑。

## 决策

探索器的跨包手势总线（`ui-sdkwork-explorer/src/client/bus.ts`）增加第三条通道 `sdkwork:explorer:open-diff`，携带 `{ path, cwd, hunks }`。`ui-chat` 的 `openFile`——所有工具行文件链接必经的唯一接缝——在调用方传入已应用 hunks 时派发它；`ToolRow` 现在只要行上渲染了 diff 卡片就随点击携带 hunks。已加载的探索器总是认领该手势并打开一个 **diff 标签页**：Monaco diff 编辑器（VSCode 的 git diff 渲染所用的同一内核）呈现在 hunks 重建出的前像与后像之上，带词级高亮、可折叠的未变区域、minimap 与合并/分栏切换。编辑器代码块导入完成前，同样的 hunks 经原语 `DiffBlock` 渲染，标签页先即时着色、再原地升级。头部统计变更数量并提供「源码编辑」按钮，经既有的 `openFileSource` 打开被改文件的可编辑源码标签页——预览保持只读，源码标签页是它的编辑面。

已应用的 hunks 本来就以工具结果元数据的形式持久化在会话日志里，因此预览重放安全：历史会话不碰文件系统即可重新渲染同一 diff。`diffPairModel` 按文件顺序从 hunks 重建两侧，相邻 hunks 之间插入与 `patchReconstruct` 相同的省略哨兵行；diff 编辑器对齐哨兵，每个 hunk 的变更高亮落在自己的行上。

标签页账本对每个文件只保留**一个变更标签页**：同一路径的第二次 open-diff 手势就地刷新既有标签页的 hunks 并激活它（VSCode 工作区 diff 的语义），因此进一步编辑之后再点击文件，看到的是最新变更而不是堆叠的过期标签页。刷新时 diff 编辑器的两个 model 只交换文本值，编辑器实例存活。

该手势绕过文件打开方式策略并总是认领。打开方式设置（内置窗口 / 系统应用 / 每次询问）管辖的是*文件*在哪里打开；变更预览没有系统应用这一臂——操作系统没有可以接手 hunks 的补丁查看器——询问只会在唯一有意义的终点前加一步。畸形 hunks（不是数组，或条目缺少字符串 `path` 与字符串 `newText`）保持未被认领，派发方的普通文件臂仍会让这次点击有着落。

MonacoFileView 的启动修复有意并入本次变更：diff 标签页复用了文件标签页的三段式结构（回退、内核启动、宿主切换），而修复确立的规则正是两者能工作的前提——**Monaco 标签页主体的宿主元素必须从首次渲染起保持挂载，内核启动时只翻转 `hidden` 状态**，因为启动回调在动态导入解析完成的时刻靠 ref 找到这个元素。先返回回退分支、后再渲染宿主的形状无法满足这条规则。

## 曾考虑的替代方案

**继续打开普通文件。** 否决：仅有变更后的全文回答不了"改了什么"，而这正是用户点击一个被改文件的原因；行内 diff 卡片上限八行，撑不起复核表面。

**用原语 `DiffBlock` 渲染整个标签页主体（不引入 Monaco）。** 否决：探索器的编辑器标准是 VSCode 内核；`DiffBlock` 没有词级高亮、折叠、minimap 或分栏布局。它留在真正产生价值的位置——预启动着色与会话行内。

**让 diff 手势也走打开方式策略与询问气泡。** 否决：询问气泡的系统应用之臂对补丁毫无意义，而横在唯一有意义终点前的策略门只会拖延点击。"总是认领"正是"点击被改文件落在它的 diff 上"可预期的原因。

**打开时从文件系统或 git 现算变更。** 否决：已应用的 hunks 本就是持久会话数据；从 git 现算在仓库外会失败、可能与工具实际应用的变更不一致，并破坏历史会话的重放。

## 后果

编辑/写入行里的文件路径点击后，落在探索器右栏的已应用变更 diff 预览上——新增与删除的行直接可读，附变更计数、合并/分栏切换，以及打开可编辑源码标签页的「源码编辑」按钮。进一步编辑之后再次点击同一文件，预览就地刷新。未加载 explorer 插件时，点击保持历史的普通文件行为：手势总线无人认领，原生打开器照常运行。测试钉住形状：`diff-tab.client.spec.tsx`（手势认领及其策略绕过、畸形手势回退、每文件单标签页刷新、hunk 到前后像的重建、标签页主体先回退后启动的升级、头部计数、布局切换与源码编辑可供性——均跑在桩 Monaco 内核上）、`tool-row.client.spec.tsx`（变更行随点击携带 hunks，无卡片行不携带），以及 `apply-inject.client.spec.tsx`（按 cwd 解析的 diff 派发与未认领时经普通文件臂的回退）。本 note 记录的 MonacoFileView 启动规则——宿主自首次渲染起挂载、启动时只翻转 `hidden`——是源码标签页能够编辑的前提；未来若回到不渲染宿主就提前返回的回退形状，所有标签页会再度无声地滞留在回退视图上。
