## 目标

让 `build:lib:client`（即 `tsc -b tsconfig.client.json && node scripts/run-tsdown-build-face.mjs client`）不再每次构建都静默执行约 2 分钟的"client 测试全量聚合类型检查"（root noEmit 聚合工程）。构建只做产物必需的工作：引用工程增量 emit（warm ~1s）+ tsdown 打包；测试聚合检查保留在 `pnpm typecheck` 与 CI typecheck gate（语义已获你确认接受）。

## 方案：把测试聚合从构建 solution 中拆出（references 单一来源，零重复）

**1. `tsconfig.client.json` 改为"构建专用 solution"**
- 删除 `include`/`exclude` 及聚合相关注释（`composite:false` + `noEmit:true` 外壳保留，files 为空 → root 工程为空、`tsc -b` 只构建 ~96 个引用工程并 emit `lib/types`）。
- 更新头部注释说明职责变化；references 列表保持唯一（上游 merge 加包时只需改这一处）。

**2. 新建 `tsconfig.client.tests.json`（root 级，fork 自有文件）**
- 继承 `tsconfig.base.client.json`；复制原聚合的 compilerOptions（noEmit、`types:["node"]`、rewriteRelativeImportExtensions:false 等）。
- 原 `include`/`exclude` 整体平移（407 个 client 测试、`*.client.*` spec、css-modules.d.ts、`packages/client/tsdown.client.ts`、`client-build-environment.ts`、scripts client specs、ui-sdkwork-* tests 排除清单等），注释保留排除原因。
- 无 references；通过 `tsc -b` 运行以保留 tsbuildinfo 快路径（warm 秒过）。
- 只被 typecheck 路径引用，不进 build。

**3. `package.json` 脚本**
- `build:lib:client` 文本不变（tsconfig.client.json 已变轻）。
- `typecheck:contracts-ready` 改为 `tsc -b tsconfig.client.json && tsc -b tsconfig.client.tests.json`——gate 覆盖与现状完全一致（refs + 合并测试程序），CI 不变。

**4. 依赖脚本与测试指向新配置（聚合 include/exclude 的归属者变了）**
- `scripts/sdkwork-dependencies.ts`：`checkDependencyOnlyWorkspaces` 改读 `tsconfig.client.tests.json`；同步更新 `scripts/sdkwork-dependencies.spec.ts` 的断言文本/夹具。
- `scripts/client-tsconfig.spec.ts`：CSS 声明加载断言改指 tests 配置；顺带加一条防漂移断言：tsconfig.client.json 的 program 文件数必须为 0（防止构建 solution 重新长回聚合）。
- `tsconfig.json`（根 solution）：在 references 中加入 `./tsconfig.client.tests.json`（与 tsconfig.client.json 并列），保持 IDE/tsserver 对测试文件的覆盖；验证 `tsc -b tsconfig.json` 行为与现状一致。

**5. 文档与注释**
- 更新 `tsconfig.client.json` / 新配置文件头部注释、`tsconfig.base.client.json` 注释中已失效的表述（若涉及 `pnpm build` 会类型检查测试的说明则一并修订，双语站点文案按 docs/AGENTS.md 规则最小化处理）。
- 新增 Agent Note（`.agents/notes/implemented/architecture/`，按仓库命名与分类约定）。

## 预期效果

- `build:lib:client`：warm ~1s tsc + tsdown ~40-90s（有逐包输出）≈ 1-1.5 分钟，无静默卡段；改动后也只有被改包重建（秒级），不再付 ~2 分钟聚合。
- `pnpm typecheck` / CI typecheck gate：覆盖不变，依旧能拦住测试类型错误。
- dev-web watch 循环（`scripts/dev-web.ts` 的 `tsc -b tsconfig.client.json` watch 阶段）自动受益，不再每次源码改动触发聚合重查。

## 验证清单（实施后执行）

1. 文件集对等：脚本对比"改动前 tsconfig.client.json 解析出的文件集" vs 新 tests 配置解析结果，须完全相等（无覆盖丢失）。
2. `tsc -b tsconfig.client.json`：warm ~1s；对测试文件做内容改动后再跑仅秒级。
3. `tsc -b tsconfig.client.tests.json`：warm 秒过；改动后执行全量检查且能报错（先注入临时错误验证可检出，再还原）。
4. 完整 `npm run build:lib:client` 计时验证。
5. 跑相关 spec/gate：`sdkwork-dependencies.spec`、`client-tsconfig.spec`、`project-reference-faces` gate、`tsc -b tsconfig.json` 行为对比；按 dsh-pre-push-checks 选取最小集（含 lint/doc 门）。
6. `pnpm clean` 不误删新配置文件（root tsbuildinfo 已被全局 *.tsbuildinfo 规则覆盖）。

## 风险与边界

- `tsconfig.client.json` 是与上游共享的文件：删除 include 后上游 merge 可能偶尔冲突，按仓库既定 fork-first/两边合并流程处理（references 列表仍是唯一来源，无新增漂移面）。
- 本改动不触碰产物路径：tsdown 消费的 `lib/types` 仍由引用工程 emit，与聚合无关（已核实测试 import 经 tsconfig paths 指向 src，聚合不依赖 refs 产物）。
- tsdown 全量重打包（~40-90s）本次不动，作为后续可选优化。
