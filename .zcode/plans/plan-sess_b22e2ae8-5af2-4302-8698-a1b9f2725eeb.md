## 目标

在"模型"设置页新增两个 OpenAI 兼容中转提供方，与 `openrouter` 完全同等的体验（出现在"添加提供方"下拉、配置 API Key 后启用、支持"获取模型"拉取完整模型列表）：

- **sdkwork** → `https://api.sdkwork.com/v1`（用户已确认域名，修正了此前选择的 .ai）
- **birdcoder** → `https://api.birdcoder.com/v1`（与 sdkwork 实现完全一致）

两者均作为 llm-pi-ai 包的"随产品发布的目录提供方"（harness-shipped catalog providers）注册，无需新建包、无需改动 LlmRuntime/Service Definition。

## 实现（核心改动集中在 packages/llm/llm-pi-ai/）

### 1. `src/catalog.ts` — 新增随产品发布的目录条目
- 新增常量 `HARNESS_RELAYS`（key 即路由名）：`sdkwork`（displayName `SDKWork`、baseUrl `https://api.sdkwork.com/v1`）与 `birdcoder`（displayName `BirdCoder`、baseUrl `https://api.birdcoder.com/v1`），共享 `api: 'openai-completions'` 与一份种子模型清单。
- **种子模型清单**：约 12-15 个主流模型，id 与容量（contextWindow/maxTokens）取自 pi-ai 自带 openrouter 目录的真实数据（vendor/model 格式，如 `openai/gpt-4o`、`openai/gpt-4o-mini`、`openai/gpt-4.1`、`anthropic/claude-opus-4.5`、`anthropic/claude-sonnet-4-5`、`anthropic/claude-haiku-4.5`、`deepseek/deepseek-chat`、`deepseek/deepseek-r1`、`google/gemini-2.5-pro`、`qwen/qwen3-max`、`z-ai/glm-4.6`、`moonshotai/kimi-k2` 等，实施时从 openrouter.json 数据中核对实际存在的 id）；input `['text']`、reasoning 走 pi-ai baseURL 自动探测（与 acme-gateway 示例一致）。完整列表由现有"获取模型"按钮（GET {baseURL}/models，discovery.ts 已支持）拉取。
- 扩展四个函数使 harness 条目成为一等目录成员（与 pi-ai 内置提供方完全同路径）：
  - `catalogProviderIds()`：`[...getBuiltinProviders(), ...Object.keys(HARNESS_RELAYS)].sort()`（保持下拉字母序，pi-ai 现有 id 排序不变）；
  - `catalogProvider(id)`：对 harness 条目用 `createProvider` + `openAICompletionsApi()`（与 provider.ts 相同 import，无新循环依赖）+ apiKey auth 构造真实 Provider（缓存），使 `buildProvider` 的复用路径（`reuseCatalogProvider` 委托 stream）与 `catalogProviderTakesApiKey` 原样工作；
  - `catalogModels(id)`：harness 种子模型物化为 `Model<Api>`（api/baseUrl/provider/input/cost/reasoning 由 harness 条目盖印，baseUrl 为各自中转站地址）；
  - `resolveRouteModels` 无需改动：`sdkwork: {}` 空 profile 即可解析出可服务的路由。

### 2. `src/config.ts` — 一处小改
- `resolveProfiles` 中 displayName 回退链改为 `source.displayName ?? harnessEntry(provider)?.displayName ?? provider`，配置后卡片显示 `SDKWork`/`BirdCoder`（导入 catalog.ts 的查找函数，无循环）。

### 3. 单元测试（保持 llm-pi-ai/src 每文件 100% 覆盖率）
- `tests/catalog.spec.ts`：`catalogProviderIds()` 含 sdkwork/birdcoder 且保持字母序；`catalogProvider('sdkwork')` 构造正确（baseUrl/auth.apiKey）；`catalogModels('sdkwork')` 种子非空且 baseUrl 为中转站地址；dormant 目录注册测试（`bootWithSettings` 后 `listConfigurableProviders()` 含两路由、declared:false）。
- `tests/config.spec.ts`：`resolveProfiles({ sdkwork: {} })` 可服务（piProvider.id、模型 baseUrl、api=openai-completions、displayName）；birdcoder 同；profile 显式 displayName 覆盖。
- `tests/adapter.spec.ts`（如适用）：走 mock-server 对 harness 路由做一次流式冒烟（与现有 gateway 测试同模式）。
